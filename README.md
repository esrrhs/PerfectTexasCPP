# texas_cfr

德州扑克不完全信息博弈求解器，C++17 实现，无第三方依赖。

核心是 **CFR（Counterfactual Regret Minimization，反事实遗憾最小化）** 家族算法。这是
Libratus、Pluribus、DeepStack 击败人类职业选手时用的方法，而**不是** PPO / DQN 这类
标准强化学习。

## 为什么不用普通强化学习

德州扑克是**不完全信息博弈**：

| | 完全信息（围棋/象棋） | 不完全信息（德州扑克） |
|---|---|---|
| 决策点 | 局面唯一确定 | 信息集内无法分辨（对手底牌有多种可能） |
| 数学框架 | MDP | 扩展式博弈 + 信念分布 |
| 最优解 | 确定性策略（选价值最大的动作） | **混合策略**，必须按概率随机出招 |
| 求解目标 | 最大化收益 | 逼近**纳什均衡**（任何固定打法都会被剥削） |

所以这里求的不是"最优动作"，而是"让对手无法利用的策略分布"。

## 算法

CFR 每一轮迭代做四件事：

1. 用当前策略遍历博弈树，算出每个信息集里每个动作的反事实价值 `v(I,a)`
2. 累积遗憾 `R(I,a) += v(I,a) − v(I,σ)`
3. 后悔匹配更新策略：`σ(I,a) ∝ max(R(I,a), 0)`，越后悔的动作做得越多
4. 按到达概率加权累积**平均策略** `σ̄`

输出的是 `σ̄`，不是最后一轮的 `σ`。理论保证平均策略的可利用度以 `O(1/√T)` 收敛到 0。

本仓库实现了三个变体：

- **vanilla CFR**：标准形式
- **CFR+**：遗憾裁剪到非负 + 交替更新 + 线性加权平均，实测快 1.4 倍以上
- **DCFR**（无限注德州的默认）：在 CFR+ 基础上再按迭代轮数给正/负遗憾和平均策略打折

DCFR 的折扣来自 Brown & Sandholm (2019)：正遗憾打 `t^1.5/(t^1.5+1)`、负遗憾打
`t^0.5/(t^0.5+1)`、平均策略打 `(t/(t+1))^2`。直觉是"越早的迭代越不可信"，负遗憾打折
比正遗憾快等于允许策略较快放弃坏动作。实测同轮数下遗憾上界只有 CFR+ 的
0.51（4万轮）→ 0.42（10万轮）→ 0.37（20万轮），比值随轮数单调下降。

几个实现要点：

- **反事实加权**：累积遗憾时只乘对手的到达概率，不乘自己的——这正是"反事实"的含义
- **整数信息集键**：避免每次递归都构造 `std::string`，Leduc 上快一个数量级
- **O(n) 牌力评估**：13 位顺子表 + 花色/点数计数，比"21 组合 × 5 张评估"快 19.5 倍
- **模板化的游戏接口**：求解器与具体游戏零耦合，新增游戏只需提供静态接口
- **强度可测量**：策略可存盘成冻结基准，`match` 子命令拿两份策略对打并给出置信区间。
  零和对称游戏里自对局恒为 0、打随机对手又太软，只有固定基准对打才有分辨力

## Leduc 规则

- 6 张牌：J,J,Q,Q,K,K，两人各发 1 张私有牌，各放 1 注 ante
- 两轮下注。第一轮下注额 2，**第二轮翻倍为 4**（Southey et al. 2005 的标准定义）
- 每轮最多 2 次加注（首次下注记作第 1 次），第二轮开始前翻 1 张公共牌
- 成对（手牌 rank == 公共牌 rank）胜过非成对，都非成对时比 rank

## 无限注德州（完整规则）

`holdem.hpp` 是完整的无限注德州规则引擎：

- 52 张牌、四条街（翻牌前 / 翻牌 / 转牌 / 河牌）
- 无限注下注，每街最多 3 次加注（够打到 4-bet）
- 加注尺寸分街处理：翻牌前按当前最大投入的 2.5x / 4x（开池、3-bet、4-bet 自然成阶梯），
  翻牌后按底池比例的 半池 / 一池；always 额外提供 all-in
- all-in 后一次发完剩余公共牌、**边池分层结算**、摊牌比牌，支持 2～6 人
- 盲注、行动顺序、无人下注时不可弃牌等边界都有单测覆盖

### 为什么必须抽象

HUNL 原始决策点约 10^160，这里做两层压缩。

#### 1. 牌力抽象（`strength.hpp`）

分三段，逐段控制精度损失。

**翻牌前：169 类手牌全分辨率使用，不分桶。** 这一条非常关键：翻牌前本来只有 169 个
可区分信息（13 个对子 + 78 个同花 + 78 个非同花），再压成 10 个桶会把 AA 和 KK、
AKs 和 AKo 合并成**同一个信息集**——策略上就是完全相同的动作分布。早先版本就是这样，
输出里 AA 和 KK 的策略逐位相同。类内所有具体组合对随机对手的胜率严格相等（花色置换
对称），所以每类取一个代表组合、用 3 万次蒙特卡洛估胜率就够。

**翻牌后百分位：精确秩表，不是分位点近似。** 5 张牌用 C(52,5) 精确枚举，6/7 张用
150 万 / 200 万次采样。关键观察是"7 张牌里最佳五张"的**不同取值只有不到 7500 种**
（5 张恰好 7462 种），所以"分数 → 严格小于它的组合数"可以完整存下来，表只有几十 KB，
查询是精确百分位，二分定位。

早先用 4096 个分位点近似，量化步长 1/4096 ≈ 0.0244%，而"四条"整个牌型只占 0.024%
的牌——**一个牌型比一个量化步长还窄**，结果四条和同花顺被压成同一个百分位。

**翻牌后潜力修正。** 只看"当前最佳五张的排名"会严重低估听牌：花听在当前牌力里只是
高牌（百分位 0.46），实际价值接近中等成牌。所以按听牌出路（outs）用超几何分布算命中
概率，对百分位做期望修正：

```
eff = (1 - p_hit) * 当前百分位 + p_hit * 命中后的百分位
```

`p_hit` 用精确的 `outs / 未见牌数`（两张牌到来时用 `1 - C(a,2)/C(b,2)`），outs 按具体
牌去重后数（花听 9 个，两头顺 8 个，卡顺 4 个）。命中后的百分位取该牌型在本张数下的
区间中点——边界不是写死的常数，而是从真实分数分布里取的。

#### 2. 分桶：按牌型分配，不是等质量分位

这一步是**不能用等质量分桶**的。5 张牌里"两对及以上"只占 8.2%，20 个等质量桶下，
两对、三条、顺子、同花、葫芦、四条会**全部挤进最后一个桶**——模型分不清"超对"和
"暗三条"，翻牌后策略直接废掉，而且这不是加迭代数能救的。同理，任何单调变换都救不了，
因为问题在于给尾部分配了多少质量，不是映射形状。

所以九个牌型各自拿到一段百分位区间，区间内部再等分成若干子桶，桶位按牌型权重用最大
余数法分配（总数精确等于 `--buckets`）。牌型边界同样由真实分布得出，5/6/7 张各不相同。

效果（20 桶，九个牌型各构造一手牌验证）：

```
高牌=1 一对=6 两对=9 三条=10 顺子=13 同花=15 葫芦=16 四条=18 同花顺=19
```

严格单调、互不重叠。等质量分桶下这里是 `… 两对=19 三条=19 顺子=19 同花=19 葫芦=19`。

因为作用在潜力修正后的 `eff` 上，听牌被抬起来之后可以跨过牌型边界往上走，不会被人为
压在底层。

#### 3. 动作抽象

每个决策点最多 5 个动作（弃牌 / 跟注 / 两个加注尺寸 / all-in），每街最多 3 次加注。

早先版本翻牌前用的是底池比例：底池只有 3，算出来的加注是"加到 4"和"加到 5"，而下一个
选项直接就是全下 200。**中间 5 到 200 之间有 195 个筹码的空洞**，模型想造大底池只能全下，
策略退化成"要么跛入要么推"。翻牌前改用当前最大投入的倍数就解决了。

### 求解器

`mccfr.hpp` 用 external sampling MCCFR：轮到 traverser 展开全部动作，对手和机会节点各
采样一个。全树遍历不可行——光翻牌就有 C(48,3)=17296 种组合。

信息集 =（街，牌力桶，下注历史），这才让"具体手牌"塌缩成有限状态。

两处关键实现：

- **整副公共牌在根节点一次抽定。** 这与逐街条件抽牌的联合分布完全相同，但整棵树共用
  一副公共牌，"牌力桶"就能按 (玩家, 街) 在本轮内缓存——实测每轮桶计算从 74 次降到 8 次，
  吞吐直接翻 2.48 倍。缓存用 `bucketStamp_[p][bc] == iter_` 做版本标记，跨轮自动失效。
- **下注历史用增量哈希。** `State` 里存 64 位哈希 + 定长字符缓冲，`next()` 里 O(1) 更新。
  早先用 `std::string`，每个节点拷一次堆分配、每个信息集键把整条历史重新哈希一遍。

遗憾累计默认用 DCFR（`--variant cfrplus` 可切回），折扣因子每轮算一次就够——一轮遍历
里一个信息集最多被更新一次。

信息集表是平坦开放寻址而非 `std::unordered_map`：遍历里每个决策节点都要查一次，
`unordered_map` 的指针追逐很贵。扩容只在两轮之间做（`prepare`），因为 `traverse` 会跨
递归持有 `InfoSetData&`，一旦中途 rehash 引用就悬空了。

### 已验证

牌力评估（确定性）：

- `evaluateBest` 快路径与 21 组合暴力实现**逐位等价**：C(52,5) 全量 2598960 组、
  C(52,6) 全量 20358520 组、随机 500 万组 7 张，**0 处不一致**
- 速度 734ns → 37ns（19.5 倍）
- 秩表规模自洽：5 张不同牌力取值恰好 7462 种，与扑克理论公认值一致

牌力抽象（确定性）：

- 翻牌前 169 类各自独立：AA/KK、AKs/AKo、AA/72o 类号互不相同，花色置换不变
- 胜率排序 AA 0.856 > KK 0.822 > QQ 0.799 > AKs 0.676 > AKo 0.659 > 72o 0.340
- 同一块 K72 面上 `AhTh` 与 `AdTd` 的**当前牌力百分位严格相等**（都是 A 高牌，都是 0.463），
  但前者有 9 个花听出路，修正后 0.463 → 0.650，必须显著更高
- 两头顺听牌 8 个出路、卡顺 4 个；河牌没有后续牌，修正退化成百分位本身
- 九个牌型在 20 桶和 50 桶下都严格单调、互不重叠

规则引擎：

- 盲注、行动顺序、翻牌发牌、无人下注不可弃牌
- 摊牌比牌、弃牌结算、两人零和
- 三人边池：主池 150 由三人争、边池 100 由 P1/P2 争，两种赢家情形下净收益和均为 0
- all-in 后一次发完 5 张公共牌并摊牌

求解器（确定性）：

- 存盘 / 读盘往返后，两手牌的平均策略**逐位相同**，信息集数与轮数也一致
- 读不存在的文件返回失败而不是崩溃
- 同一策略在两个座位自对打，结果落在 0 的置信区间内（校验 `headToHead` 的座位对称性）
- 遗憾上界随轮数下降；同轮数下 DCFR 严格低于 CFR+（10 万轮实测比值 0.42）

策略（统计量，非确定性）：

- 15 万轮后：AA 加注 0.782 / 弃牌 0.000；72o 加注 0.013 / 弃牌 0.968
- 该断言用 8 个种子各跑 15 万轮实测过：`raiseAA/raise72` 最小 3.7、AA 弃牌恒为
  0.000、72o 弃牌最低 0.789。阈值留了一倍余量，不会再随随机流摆动

### 怎么判断"确实更强"

零和对称游戏里**自对局恒为 0**，打均匀随机对手又太软抓不住差异，所以强度验证必须
有个固定基准。`save` / `load` + `match` 就是为此存在的：

```bash
# 1. 冻结一个基准，之后永不重训
./build/texas_cli holdem --iters 500000 --variant cfrplus --save base_cfrplus.bin

# 2. 候选策略（多个种子）逐个对打
for s in 1 777 12345 99991 31337; do
  ./build/texas_cli holdem --iters 500000 --seed $s --save cand.bin
  ./build/texas_cli match --a cand.bin --b base_cfrplus.bin --hands 600000
done
```

这个协议有两个坑，都踩过：

- **单个基准快照自带强度偏移。** CFR+ 用不同种子对打同一个 CFR+ 基准，结果不是 0 而是
  **+0.122 ± 0.062**（5 个种子全为正）——说明那个基准恰好比平均弱一点。所以不能拿
  "相对基准的绝对收益"当结论，要用**两个候选取差值**，基准偏移 β 在相减时抵消。
- **分辨率要算清楚。** 每手净收益的标准差约 149 筹码（全下就是 ±200 的摆动），
  想分辨 0.05 筹码/手需要 `(149/0.05)² ≈ 890 万手`。

DCFR 与 CFR+ 的对照（同 50 万轮、20 桶、5 个种子、每组 120 万手）：

| 候选 | 相对基准每手净收益 | 遗憾上界 |
|---|---|---|
| CFR+ | +0.122 ± 0.062 | 116.6 |
| DCFR | +0.450 ± 0.078 | 36.9 |
| **差值（DCFR − CFR+）** | **+0.328 ± 0.100（3.3σ）** | 约 1/3 |

单份快照对打（DCFR 20 万手 vs CFR+ 20 万手，两座位合计 80 万手）复现出更大的
**+0.7335 ± 0.1566**，那是含了快照自身波动的数值，所以区间比多种子均值更宽。

策略合理性上 DCFR 也一并修掉了一个老毛病——**AA 平跟**：

| | CFR+ 50 万轮 | DCFR 50 万轮 |
|---|---|---|
| AA 平跟 | 0.69 | 0.25 |
| AA 加注合计 | 0.31 | 0.75 |
| AA 全下 | 0.07 | 0.00 |
| 72o 弃牌 | 0.88 | 0.97 |
| QJs 全下 | 0.26 | 0.01 |

### 还没做的

- **策略只到"趋势正确"，没到可利用度可测的水平，而且瓶颈明确就是迭代数。** 38344 个
  信息集，50 万轮下平均每个只有约 13 次更新，翻牌前某个具体手牌类更是只有约 450 次。
  典型症状是翻牌前对全下的过度偏好：

  | 轮数 | KK 全下 | 22 全下 | 遗憾上界 |
  |---|---|---|---|
  | 25 万 | 0.816 | 0.884 | 62.0 |
  | 50 万 | 0.539 | 0.734 | 36.6 |
  | 100 万 | 0.405 | 0.354 | 22.3 |
  | 200 万 | 0.131 | 0.157 | 14.1 |

  两点都**单调下降**，所以这是收敛滞后而不是系统性偏差（早先怀疑过 CFR+ 的遗憾裁剪会
  系统性地偏向高方差动作，但 DCFR 不裁剪、症状相同且同样单调收敛，说明这个猜想不对）。
  用 8 万次 MC 探针直接量根动作价值也确认了偏差的方向：50 万轮时 KK 加注到 8 是
  +40.5 筹码、全下只有 +33.4，即"全下"每手白扔约 7 筹码；22 是弃牌 −1.00、全下 −1.29。

- **抽象仍是粗的。** 20 个桶、翻牌前 5 个动作、每街 3 次加注，这些都是为了让 MCCFR
  在几十万轮内能跑出东西。尤其是"独立的全下动作"——100BB 深筹码下它和 2.5x/4x 之间
  隔着一个巨大的尺寸空洞，是过度全下的温床之一。
- **前一版 README 里记的"新旧抽象对打打平"结论要修正。** 当时用 10 万手/组、单次快照，
  现在知道那个分辨率（约 ±0.5 筹码）根本测不出差异；而且单个基准自带 ±0.12 的强度偏移。
  换成多种子 + 120 万手/组之后，DCFR 与 CFR+ 的差值才稳定在 3.3σ。**评估工具的分辨率
  不足时，"打平"这个结论本身是不可信的。**
- 要让策略真正可用，路线是：蓝图策略 + 实时子博弈求解（DeepStack / Libratus 路线），
  或者把 MCCFR 换成公有树 + 手牌向量化的向量化 CFR，用 GPU 跑。
- 分桶还可以再往前走一步：potential-aware 的二维特征（当前胜率 × 后续街胜率）加
  OSS / k-means 聚类，而不是现在的一维投影。
