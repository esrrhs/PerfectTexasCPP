# PerfectTexasCPP

单挑无限注德州（Heads-Up No-Limit Hold'em）的**自对局强化学习**，C++17 + LibTorch，
训练循环全是 C++，没有 Python。

这一版把原来的 CFR / MCCFR 求解器整个删掉，换成和兄弟项目
[PerfectDouCPP](https://github.com/esrrhs/PerfectDouCPP) 同一套算法：
**不完全信息 Actor + 开天眼 Critic 的完美信息蒸馏 + PPO**。行为序列和底牌一起进特征，
不再查信息集表。

## 一、改了什么

| | 重构前 | 重构后 |
|---|---|---|
| 算法 | CFR / CFR+ / DCFR / external-sampling MCCFR | PPO + GAE + 完美信息蒸馏 |
| 策略表示 | 信息集哈希表（街 + 牌力桶 + 下注历史） | 神经网络，输入 = 底牌 + 公共牌 + 行为序列 |
| 动作抽象 | `ActionSpace` 预设，最多 7 个动作 | 8 个全局槽位（弃 / 跟 / 5 档尺寸 / 全下） |
| 对手 | 无（两人零和自对局恒为 0） | 联赛：最新 + 两级历史池 + 规则机器人 + 随机 |
| 评估锚点 | 可利用度（完全遍历）+ 存盘策略对打 | 规则机器人 + 随机 + 自对局 |
| 依赖 | 零依赖，header-only | LibTorch（Actor/Critic 用 `torch::nn`） |
| 代码量 | 4800 行（含 Kuhn / Leduc / BR） | 约 3400 行（规则 / 特征 / 采样 / PPO / 网络 / CLI） |

删掉：`cfr.hpp`、`mccfr.hpp`、`br.hpp`、`kuhn.hpp`、`leduc.hpp`、`equity.hpp`、
`holdem.hpp`（多路 + 边池的规则引擎，换成单挑专用的 `hu.hpp`）。
留下：`card.hpp`（52 张牌与 O(n) 牌力评估）、`strength.hpp`（169 类翻前胜率表、
翻后精确百分位、听牌出路）——牌力评估和牌力抽象这两块是旧版最硬的部分，没必要重写。

### 规则口径：对齐 ACPC

规则不再是自定的，全套按 ACPC（Annual Computer Poker Competition）的 HUNL 配置来。
完整的规则说明（牌局流程、合法动作、结算、边界情况、逐条对账）在 **[docs/RULES.md](docs/RULES.md)**，
这一节只放结论：

| | ACPC（`holdem.nolimit.2p.reverse_blinds.game`） | 本引擎 |
|---|---|---|
| 起始筹码 | `stack = 20000` | `kStartingStack = 20000` ✅ |
| 盲注 | `blind = 100 50` | `kSmallBlind=50 / kBigBlind=100` ✅ |
| 深度 | 200BB | 200BB ✅ |
| 每街加注上限 | 无（只要求不小于上次下注或大盲） | 无 ✅（`--max-raises 0`） |
| 下注金额 | **任意整数**，只要 ≥ 最小加注、≤ 剩余筹码 | **任意整数** ✅（尺寸带 + 带内连续落点） |
| 最小加注 | 上次下注额 与 大盲 取大 | 同 ✅ |
| 行动顺序 | 小盲翻前先动、大盲翻后先动 | 同 ✅ |
| 筹码重置 | 每手重置（Doyle's Game） | 同 ✅ |

**和 ACPC 唯一的差别是"按钮归谁"**：ACPC 的 2 人桌用反向盲注，按钮位下大盲；
这里沿用常见的按钮 = 小盲。两者只是记账口径不同，游戏树（谁先动、谁下多少）完全
一样，所以不影响策略。

三处旧版的偏离已经改掉：

| | 旧 | 现在 |
|---|---|---|
| 深度 | 100BB（200 筹码 / 1-2 盲注） | **200BB** |
| 加注上限 | 每街 3 次（4-bet 封顶） | **无上限**（实测最小档能连加 60 次） |
| 下注金额 | 5 个固定尺寸 | **任意整数金额**（带内连续，见第二节「动作」） |
| 单位 | 筹码/手、bb/100 | 增加 **mbb/g**（ACPC 标准口径） |

`--max-raises N` 可以退回"每街 N 次加注"做对照（深度仍是 200BB，改深度要动
`kStartingStack` / `kBigBlind` 两个常量）。

**代价要说清楚**：深度翻倍，单手标准差也从 46.8 BB 涨到 90.6 BB（未训练策略实测，
见第五节「基线」）。按起始筹码归一化后基本不变（0.47 → 0.45 个买入），但评估要的是
**bb/100 分辨率**，σ 几乎翻倍 → 同样精度需要 **近 4 倍样本量**：同样 8000 手，100BB 能给
±52 bb/100，200BB 只给 ±101。训练日志里的归一化回报标准差则几乎不动（300 轮均值
0.640 → 0.622），换成 BB 单位也是 64BB → 124BB，和上面同一条规律。
ACPC 当年的参赛队为此跑**上千万手**，这不是工程量问题，是数学。


单位换算：`1 bb/100 = 10 mbb/g`。永远弃牌的基线是 **−750 mbb/g**（大盲丢 1000、
小盲丢 500），实测本引擎正好是这个数——这条已经写进测试当不变式。

### 和 ACPC 的逐条对账

规则层面对着 [ACPC protocol v2.0.0](http://www.computerpokercompetition.org/downloads/documents/protocols/protocol.pdf)
和 `holdem.nolimit.2p.reverse_blinds.game` 逐条核过：

| 项 | ACPC | 本引擎 | |
|---|---|---|---|
| 起始筹码 | `stack = 20000 20000` | `kStartingStack = 20000` | ✅ |
| 盲注 | `blind = 100 50` | `50 / 100` | ✅ |
| 每手重置 | Doyle's Game | 每手重置 | ✅ |
| 轮次 / 牌 | 4 轮、2 底牌、公共牌 0/3/1/1 | 同 | ✅ |
| 行牌顺序 | `firstPlayer = 2 1 1 1`（按钮下小盲、翻前先动、翻后后动） | 座位 0 = 小盲 = 按钮 | ✅（只差编号） |
| 弃牌合法性 | 只有"需要加钱才能跟"时才能弃 | `need > 0` 才给弃牌槽 | ✅ |
| 加注合法性 | raise-by ≥ 1；要么全下，要么 raise-by ≥ max(上次 raise-by, 大盲) | `minRaiseTo = lastRaiseTo + max(lastRaiseSize, BB)`，钳到全下 | ✅ |
| **短全下** | 把对手全下的加注不受最小加注限制 | 全下槽恒合法；凑不出完整加注时最小加注自动钳到全部筹码 | ✅ |
| 加注次数 | 无上限 | 无上限（实测连加 60 次） | ✅ |
| 下注金额 | 任意整数 | 任意整数（单决策点覆盖率 100%） | ✅ |
| 对手全下后 | 不能再开火 | `isRaisePossible` 检 `allin[对手]` | ✅ |
| 结算 | 单挑等额投入 → 单底池 | 单底池，无边池 | ✅ |
| 平分 | spec 只写"split evenly"，没规定奇数筹码 | 奇数筹码给座位 0 | ⚠️ 1 个筹码 = 0.005BB |
| 单位 | mbb/g，永远弃牌 −750 | 同 | ✅ |

**还剩三处没对齐，而且都不是规则层**：

1. **动作空间是抽象的。** 任意金额打得出来，但策略每个决策点只在 16 个带里选
   （+弃 / 跟 / 全下）。ACPC 的完整游戏是 19800 个动作。参赛队也都抽象，
   但抽象会带来可利用度下界，所以"规则对齐"≠"在打 ACPC 的完整游戏"。
2. **评估没做同牌对调（duplicate match）。** ACPC 每手牌用同一副牌、两个人换座位
   各打一遍，把发牌运气消掉；我们是两遍独立发牌（`runBenchmark` 只换了对手座位）。
   同样样本量下我们的标准误更大——这也是为什么 1.6 万手才 ±58 bb/100。
3. **没有可利用度基准。** ACPC 的部分赛道直接测 exploitability，我们只有
   "vs 固定基准"，所以现在的数字**不能换算成 ACPC 榜单上的强度**。
   能对上的只有永远弃牌 −750 mbb/g 这条下界标尺。

第 2 条是性价比最高的一个：做成同牌对调之后，同样的手数标准误能明显降下来
（配对差只保留"策略差异"，发牌方差被消掉）。

## 二、算法

### 两个网络，两套参数

单挑两个座位（小盲 SB / 大盲 BB）位置不对称，所以**每个座位一套 Actor + Critic**，
共 4 个网络。这和 PerfectDou 的"地主 / 下家 / 上家各一套"是同一个做法。

**Actor（不完全信息）** —— 只看得见自己该看见的东西：

```
LSTM(12 步 × 12 维行为序列) → h_last [128]
x     = concat(节点特征 388, h_last)            → 516
joint = concat(x[动作所属样本], 动作特征 16)     → 532
MLP: 532 → 256 → 256 → 256 → 512 → 1（ReLU，最后一层零初始化）
每个合法动作一个分数 → scatter 成 [B, 8] 的 logits，非法动作为 -1e9
```

`l1` 做了**分解投影**（节点部分只算一次，再按动作 gather），省掉把节点特征复制 L 遍的
开销——对应 PerfectDouCPP 的 `models.cpp`。

**Critic（开天眼）** —— 这是"开天眼、实时对齐"的另一半：

```
LSTM(同一条行为序列) → h_last
x = concat(节点特征 388, h_last, 开天眼特征 108)  → 624
MLP: 624 → 256 → 256 → 256 → 256 → 1
```

开天眼特征 108 维 = **对手两张底牌（2×52）+ 完美信息胜率 + 底池赔率 + 边际**。

它和 Actor 在**同一个进程、同一个更新循环**里同步训练：每轮先采样、再一起更新、
每 50 轮把权重快照进联赛池，没有异步延迟，也没有单独的推理服务。Actor 永远看不到
对手底牌，Critic 永远看得到——蒸馏就发生在 `A = R − V_开天眼(s)` 这一步：完美信息的
价值当基线，把"运气"从优势里扣掉，留下的才是动作的功劳。

### 特征

| 组 | 维度 | 内容 |
|---|---|---|
| 自己的底牌 | 104 | 2 × 52 one-hot |
| 公共牌 | 260 | 5 × 52 one-hot（未发出的全 0） |
| 标量 | 24 | 底池、跟注额、双方筹码、底池赔率、街、位置、SPR、加注次数、全下标志、**自己的牌力百分位**、听牌出路、翻前 169 类号 |
| 行为序列 | 12×12 | 最近 12 个动作：谁、哪条街、类型 one-hot、金额、动作后底池 |
| 开天眼 | 108 | 对手底牌 104 + 完美信息胜率 + 底池赔率 + 边际 |
| 动作 | 16 | 类型 one-hot + 金额/底池 + 金额/筹码 + 动作后底池与筹码 + 是否全下 + 是否加注 |

底牌用 52 维 one-hot 而不是 13×4 矩阵：花色关系让网络自己学，少一层手工结构。

### 动作

**金额没有预设档位**，和 ACPC 一样是任意整数。但网络输出必须有限维，所以拆成两层：

```
19 个全局槽位（kNumActions = kMaxSizes + 3）
  0            弃牌
  1            过牌 / 跟注
  2 .. 17      16 个"尺寸带"：每个带是合法加注区间里的一段连续整数区间
  18           全下
```

尺寸带不是等距切的，而是拿扑克里的常用尺寸当**分界点**，于是带本身是连续的区间：

| 街 | 分界用的锚点 |
|---|---|
| 翻前 | 上次加注额的 2.2 / 2.5 / 3 / 4 / 5.5 / 8 / 12 / 20 / 35 / 60 倍 |
| 翻后 | 跟注额之上加底池的 1/4 / 1/3 / 1/2 / 2/3 / 3/4 / 1 / 1.25 / 1.5 / 2 / 3 / 5 倍 |

相邻两个锚点之间就是一个带（`[锚点_i, 锚点_{i+1} - 1]`），最后一个锚点到全下之前
还有一段**尾带**。所以：

- 常用尺寸附近带很窄，落点精度高；
- 再大的注也打得出来——尾带覆盖到全下前一档；
- 带内是连续的整数区间，**任何合法金额都可能被取到**。

一个决策点上"槽 → 金额"的映射（翻前小盲首次行动，200BB）：

```
弃 / 跟 / [200-219] / [220-249] / [250-299] / [300-399] / [400-549] / [550-799]
/ [800-1199] / [1200-1999] / [2000-3499] / [3500-5999] / [6000-19999] / 全下 20000
```

这两行是 11 个带（槽 2..12），覆盖 200 ~ 19999 共 **19800 个整数金额**，加上弃 / 跟 /
全下共 14 个动作。同一个翻前局面在旧版里只有 8 个动作、5 个金额。

翻后又是另一套锚点：池 2000、身后 19000 时是 `过 / [100-499] / [500-666] / [667-999] /
[1000-1332] / [1333-1499] / [1500-1999] / … / 全下`。带的数量随局面在 11~12 之间浮动。

**策略采样的是槽，金额在带内落点**（对数均匀）：`π(a|s) = π(槽|s) · U(金额 | 槽)`。
因为均匀分布的密度只跟带宽有关、不带参数，PPO 的重要性比值里这一项精确抵消，
所以 `logp` 仍然只记槽的概率——训练数学不用改，这一点让改动只落在采样侧。
代价是同一个槽里不同金额的回报会混在一起估，带宽越宽噪声越大，这也是尾带被压到
"只覆盖用不到的大注"的原因。

**每街加注次数无上限**（ACPC 口径）。最小加注 = 上次加注额 + max(上次加注增量, 大盲)，
所以任意金额都会正确影响下一次的最小加注；实测一直取最小档能连加 **60 次**才被迫全下
（旧版 `kMaxRaises = 3` 在第 4 次就把牌局砍成只剩弃/跟/全下）。`--max-raises N` 可以
把上限加回来做对照。

翻前用"上次加注额的倍数"而不是底池比例，是因为翻前底池只有 3 个大盲，底池比例算出来的
尺寸全挤在 4~5 个大盲（旧版 README 里踩过一次）。

### 奖励

```
r_terminal = 净筹码 / 起始筹码            (∈ [-1, 1])
r_shape    = coef × ΔΦ                    (开天眼稠密奖励)
Φ(s)       = (开天眼胜率 × 底池 − 自己已投入) / 起始筹码
```

Φ 的含义是"从此刻起双方都不再下注时的期望净收益"，所以它是一个真正的势函数：

- 弃牌不改变底池也不改变投入 → `ΔΦ = 0`，不会凭空奖励弃牌；
- 跟注 b：`ΔΦ = b·(2·eq − 1)`，胜率过半才有正收益；
- 归一化到起始筹码是为了让奖励落在 O(1)：直接用筹码会让价值网 MSE 大得吃掉梯度
  （100BB 口径下 ±200 就实测过 MSE 上千；现在 200BB 是 ±20000，只会更糟）。

这一条**踩过一次坑**：最早的 Φ 写成 `底池 × (2·eq − 1)`，少了"自己已投入"这一项，
于是对手往底池里下注就把 Φ 推高——弃一手 60% 胜率的牌也能拿到正奖励。实测后果是
策略在 50 轮内塌成"从不弃牌"，摊牌率 44% → 80%。

### PPO / GAE

和 PerfectDouCPP 的 `ppo.cpp` / `ppo_learner.cpp` 一致：γ=1、λ=0.95、裁剪 0.2、批内
优势标准化、actor / critic 各一个 Adam（梯度裁剪 0.5 / 5.0，因为价值在筹码量级上）、
KL 早停（0.03）、掩码 softmax 带"全非法时退化成均匀分布"的兜底。

早期版本还加了一条：**策略更新完之后 critic 再多跑 8 个 epoch**。理由是价值基线
不准时，PPO 会把"稳输一小注"的弃牌算成好棋。**2026-10-26 的 600 轮同种子 A/B
推翻了这条**：额外 epoch 越多，critic 越贴当前批、跨批泛化越差（mix 从 +952
掉到 +829 / +642）；默认已改成 0。见第八节第 12 条。

### 联赛

**按局分配对手，不是按座位各自独立抽。** 每一局先抽"这一局遇上谁"，然后随机挑一个
座位放对手，另一个座位**一定是当前策略**。两个理由：

1. 独立抽会浪费算力。按 0.3 / 0.15 / 0.05 的配比，独立抽约有
   `0.3² + 0.15² + 0.05² ≈ 11%` 的牌局两边都不是当前策略——整局跑完一条样本都采不到。
   机器人比例拉到 0.5 时这个浪费会冲到 25% 以上。
2. 独立抽压根没法控制配比。要保证"每局都有一个学习座位"，只能按局指定。

对手有四种：

| 默认概率 | 对手 |
|---|---|
| 0.50 | 当前最新策略（纯自对局） |
| 0.30 | 历史快照池 |
| 0.15 | 规则机器人（牌力百分位 + 底池赔率） |
| 0.05 | 均匀随机 |

历史池是**两级**的，对应 PerfectDouCPP 的 `HistoricalPool`：

| 层 | 默认容量 | 淘汰策略 | 管什么 |
|---|---|---|---|
| `recent` | 8 | 滚动丢掉最老的 | 战术演化的最近几步，让对手记得自己上一分钟什么样 |
| `archive` | 16 | **满了隔一个丢一个**，保留间隔翻倍 | 灾难性遗忘 |

`archive` 的"隔一个丢一个"是重点：不是从最老的开始扔，而是均匀抽稀，于是老的快照越来越
稀疏但**永不消失**。只有 `recent` 时，池子永远只覆盖最近 8 次快照，策略一旦跑偏就再也
遇不到早期的自己，会在同一个坑里反复振荡——这正是之前 400 轮曲线在 ±4 之间乱跳的原因之一。
抽历史对手时 30% 从 `archive` 抽、70% 从 `recent` 抽。

规则机器人和随机策略是两种**风格完全不同**的锚点，不是凑数：规则机器人打得像人，
随机策略会频繁乱推全下。只跟其中一种练，会练出只克它的怪招（第五节有一整个反面教材）。

历史快照是为了打断自对局的循环策略。规则机器人同时充当评估锚点——CFR 删掉之后，
"到底比谁强"需要一个固定标尺，它就是那个标尺。

`--rule-prob` 是课程旋钮。拉到 0.5 会让 `vs 规则机器人` 一路涨到 +11.5，但代价是策略
退化成"不看牌的固定下注模式"——见第五节，这是把指标刷上去而不把牌打好的典型。

## 五、实测（历史：2026-10-25 旧版）

> 这一节及下一节记录的是**教师蒸馏之前**的状态：PPO 在 200BB 下跑了十几万手，
> 仍然输给规则机器人，probe 里 AA 和 72o 的输出逐位相同。保留它们是因为
> 里面的方差分析、评估手数预算、失败记录仍然有效；**当前结论见第八节**。

> **口径警告（先看这条再看数字）**
>
> 规则和动作空间改过两轮，这一节里同时躺着三套口径的数字，**互相之间不能直接比**：
>
> | 代号 | 规则 | 动作空间 | 出现在 |
> |---|---|---|---|
> | **A**（旧） | 100BB、每街最多 3 次加注 | 5 个固定尺寸 | 所有标题带「旧口径」的小节 |
> | **B**（过渡） | 200BB、无加注上限 | 5 个固定尺寸 | 「200BB 下还学得动吗」「噪声预算」 |
> | **C**（当前） | 200BB、无加注上限 | **任意整数金额** | 「动作空间放开成任意金额之后」+ 第六节 |
>
> A 和 B/C 的差别是深度（绝对值差 2 倍）和加注上限；B 和 C 的差别是动作空间——
> 同一个策略在 B 下只能打 5 个金额，在 C 下能打任意金额，**胜率数字不可平移**。
> 只有「没学会看牌」「单一基准可以刷」这类定性结论在三套口径下都成立。

```
未训练策略 vs 随机策略:   -7.213 ± 89.694 筹码/手 (-7.2 bb/100, -72.1 mbb/g)
```

未训练网络（head 零初始化 → 8 个动作等概率）每手输 1194 个筹码 = 11.9BB 一手，
这就是训练要跨过的起点。标准误 ±101：一次全下一次 ±200 的摆动，单副牌标准差约 9000 筹码
（90BB），200BB 下比旧口径吵得多。

两个参照点钉住这个数有多离谱：**永远弃牌 = −750 mbb/g（−0.75BB/手）**，
未训练网络是它的 **16 倍差**——比什么都不做还差一个数量级，因为它会拿着 72o 全下。
任何"训练有进步"的结论，都要先把这一段（1194 → 75 bb/100）跨过去。

同一起点在随机策略上约等于 0（−7.2 ± 89.7，均匀随机打均匀随机，零和对称，本来就该是 0）。
但这个 ±89.7 本身就是信息：**8000 手在 200BB 下连"是不是 0"都分不出来。**

### 200BB 下还学得动吗（口径 B：5 个固定尺寸）

规则一改，第一件事是确认"还能不能学"。300 轮 × 384 局 = **11.5 万手**，单线程 CPU：

```
$ ./perfecttexas train --updates 300 --games 384 --threads 1 --lr 1e-3 --entropy 0.02 \
    --oracle-coef 0.3 --eval-every 100 --eval-games 4000 --seed 11 --out /tmp/ck_acpc300
```

大盲正好是 100 筹码，所以这里"筹码/手"的数值**直接就是 bb/100**（不必再换算）：

| 轮数 | 累计手数 | vs 规则机器人 | vs 随机 | vs 自己（小盲视角） |
|---|---|---|---|---|
| 0（未训练） | 0 | −1193.6 ± 101.3 | −7.2 ± 89.7 | — |
| 100 | 3.8 万 | −401.7 ± 74.5 | +596.6 ± 96.9 | +107.6 ± 137.5 |
| 200 | 7.7 万 | −128.6 ± 56.4 | +608.7 ± 92.3 | −423.7 ± 146.7 |
| 300 | 11.5 万 | −151.7 ± 53.2 | +626.9 ± 99.1 | +110.8 ± 147.8 |

终点用 8000 手 × 两个座位（合计 1.6 万手）复核：

```
$ ./perfecttexas eval --resume /tmp/ck_acpc300 --vs rule   --hands 8000
rule:   16000 手, -185.705 ± 39.123 筹码/手, -185.7 bb/100, -1857.1 mbb/g
$ ./perfecttexas eval --resume /tmp/ck_acpc300 --vs random --hands 8000
random: 16000 手, +668.596 ± 69.802 筹码/手, +668.6 bb/100, +6686.0 mbb/g
```

三条读法：

1. **确实在学**：vs 规则从 −1193.6 缩到 −185.7（缩小 6.4 倍），vs 随机从 0 推到 +668.6。
   两个基准同向改善，不是刷单一指标。
2. **但离 0 还很远，而且比"永远弃牌"更差**：−1857 mbb/g，是永远弃牌 −750 的 2.5 倍。
   它现在不是"在赢"，是"在少输"，而且还不如什么都不做。
3. **第 200 轮之后曲线平了**：−128.6 → −151.7，差 23，而单次评估标准误 53~75。
   11.5 万手在 200BB 下不够，这是口径的代价，不是代码的 bug。

`vs 自己` 那一列测的是**座位 0（小盲）的收益**，而零和下大盲的收益必然互为相反数，
所以它衡量的是"网络自己的小盲被自己的大盲打得多惨"：+107.6 → −423.7 → +110.8。
中间那次 −423.7（3σ）说明网络的**大小盲两套行为不自洽**——同一个网络，换个座位就
换个水平。原因在特征里：节点特征是"我/对手"视角（`me = s.toAct`），而历史序列里的
座位位是绝对座位（`e.seat == 0`），网络得自己学这个换算。这是已知的设计债，见第六节。

### 噪声预算：评估到底要多少手（口径 B 实测）

标准误 `SE(bb/100) = 100·σ_BB / √n`，实测 `σ_BB`：

| 策略 | σ（每手） | 8000 手 → SE |
|---|---|---|
| 未训练（8 个动作等概率） | 90.6 BB | ±101 bb/100 |
| 训练 300 轮后 | 49.5 BB | ±39 bb/100 |
| 旧口径未训练（100BB，n=8000） | 46.8 BB | ±52 bb/100 |

所以训练后的模型要拿到 ±10 bb/100 的分辨率，需要 **25 万手**；±5 需要 **100 万手**。
这不是"多跑一会儿"能解决的量级——ACPC 的参赛队为此跑上千万手。
**任何"我训练了十几万手，胜率提升了 X"的说法，先在脑子里 ÷√n 再看。**


### 动作空间放开成任意金额之后（口径 C）

ACPC 的规则是"任何不小于最小加注的整数金额"，所以我们把 5 个固定尺寸也拆掉了。
具体做法见第二节「动作」：16 个**连续的整数区间（带）**代替 5 个点，策略选带、
金额在带内对数均匀落点。

**覆盖率是硬的**（单个决策点上可达整数 ÷ 合法区间里的整数）：

```
翻前 SB 首次行动      合法区间 [200, 19999]，11 个带，覆盖 19800 / 19800 = 100%
翻牌 池 200 筹码 19900 合法区间 [100, 19899]， 9 个带，覆盖 19800 / 19800 = 100%
翻牌 池 10000 筹 15000 合法区间 [100, 14999]， 8 个带，覆盖 14900 / 14900 = 100%
```

`canRaiseTo(s, 12345)` 为真，`canRaiseTo(s, 19999)` 为真，`canRaiseTo(s, 199)`（不到 2BB）
和 `canRaiseTo(s, 20001)`（超过剩余筹码）为假——**唯一的限制就是最小加注和剩余筹码**，
这正是 ACPC 的口径。加注次数也真的无上限了：一直取最小档能连加 **60 次**（200, 300, 400,
…, 6100）才被迫全下，旧版 `kMaxRaises = 3` 在第 4 次就把牌局砍成只剩弃/跟/全下。

同样的 300 轮 × 384 局（11.5 万手、0.44 轮/s，比 8 槽慢 14%）：

| 轮数 | 口径 B（5 个固定尺寸） | **口径 C（任意金额）** |
|---|---|---|
| 100 | −401.7 ± 74.5 | −340.3 ± 89.7 |
| 200 | −128.6 ± 56.4 | −225.4 ± 90.4 |
| 300 | −151.7 ± 53.2 | −31.4 ± 82.3 |

看起来 C 赢了将近 120 bb/100，但**别急着下结论**：用 1.6 万手独立复核，C 是
**−244.2 ± 58.6**，B 是 −185.7 ± 39.1，两者之差只有 0.8σ。**11.5 万手在这个方差下
分辨不出两套动作空间的差别**，上面那张表里两次抽样差了 2σ 就是这个道理。

`vs 随机` 从 +626.9 涨到 +2045.5 更不能当证据：随机对手本身也改用任意金额了（会随机
打出 1 个筹码到 199 个大盲），它自己变弱了。同理，未训练基线也从 −1193.6 掉到
**−1827.5 ± 109.7**——因为未训练策略同样开始乱打任意金额。

一句话：**放开金额让规则对齐了，没有让策略变强。**

probe 也一样：六个局面（AA / KK / AKs / 72o / K72 面上的 AA 和 72o）的输出在第 2~3 位
小数上才开始差别（`b300-399` AA 0.13 对 72o 0.12、`b550-799` AA 0.04 对 72o 0.05）。
金额是任意的了，网络依旧基本不看牌——**能力给足了，信号还是不够**。
方法层面只剩第六节第 1 条那条路：把"动作的功劳"从"牌运"里配对剥出来。

### 管线体检：给它一个已知正确的优势，它学不学得会？（旧口径）

训练不动时，先分清"链路有 bug"还是"信号太吵"。`sanity` 把优势换成**动作相关、
且已知与牌力强相关**的合成信号（强牌加注给正优势、弱牌弃牌给正优势），跑 400 轮 PPO：

```
AA   fold=0.02 call=0.01 r4=0.14 r5=0.15 r6=0.15 r8=0.16 r11=0.18 jam=0.19
72o  fold=0.31 call=0.09 r4=0.10 r5=0.10 r6=0.10 r8=0.09 r11=0.09 jam=0.13
85o  fold=0.41 call=0.10 r4=0.07 r5=0.07 r6=0.07 r8=0.07 r11=0.07 jam=0.12
```

方向完全正确（AA 弃牌 2%、加注 62%；85o 弃牌 41%）。**说明 actor / PPO / 特征 /
动作映射这条链路是通的**，真实训练学得慢不是 bug。

顺带：这个测试的第一版把优势写成"只跟牌力有关、与动作无关"，结果弱牌反而学去全下。
原因很清楚——每个动作被同等放大时政策没有偏好可学，剩下的漂移全是噪声。测试本身
也得设计对。

### 价值网的容量（旧口径）

`critfit` 把一批 508 条自对局数据固定住，只训练 critic：

```
step  100  rmse 0.0651
step  200  rmse 0.0421
step  300  rmse 0.0016     ← 这 batch 的回报标准差本身是 0.5534
```

300 步就能拟合到几乎为零（是记忆，不是泛化）。所以价值网不缺容量，训练循环里缺的是
**步数**：每轮只有约 1000 条新样本，4 个策略 epoch + 8 个价值 epoch ≈ 36 个梯度步，
而目标分布每轮都在变。

### 开天眼稠密奖励的系数：三组对照（旧口径）

单种子、512 局/轮，跑到 100 轮时的 `eval vs rule`（正数 = 比规则机器人强）：

| 组 | coef | 100 轮时 | 后续 |
|---|---|---|---|
| A | 0.05 | +0.47 ± 1.57 | **塌缩**：弃牌率 91%、小盲收池率 1.8%、熵 1.41 → 0.32 |
| B | 0.30 | **+4.57 ± 1.83** | 稳定，弃牌率 23% |
| C | 关掉 | +2.48 ± 2.22 | 稳定，但熵掉到 0.94 |

三条结论都只有单种子证据，**按后面"自对局为什么不单调"一节的结论，这几行不能当定论**，
只有"0.05 会塌缩"这一条因为伴随熵从 1.41 掉到 0.32、有独立旁证，可以算数：

1. **开天眼稠密奖励有用**：0.30 那组在 100 轮就到 +4.57，是唯一明显压过规则机器人的。
2. **系数太小反而更危险**：0.05 那组塌缩了。稠密信号太弱时，弃牌的"确定性小损失"
   相对价值基线显得更划算，策略一路滑向全弃——自对局里最常见的塌缩形态。
3. **关掉也能到 +2.48**，但熵掉得最快（0.94），说明它正往"小盲猛加、大盲狂弃"的
   退化均衡走。

### 长跑的三个基准（核心结果，旧口径 100BB）

从 −8 筹码/手起步，训练到 600 轮（约 23 万手）之后。每格都是 8000 手 × 两个座位
（合计 16000 手、同一次评估循环），不是训练日志里的抽样评估：

| 训练配置 | 轮数 | vs 规则机器人 | vs 随机策略 |
|---|---|---|---|
| 未训练（head 零初始化 → 8 个动作等概率） | 0 | −8.08 ± 1.57 | −0.79 ± 1.23 |
| 自对局为主 `--rule-prob 0.05 --league 0.30` | 400 | +2.65 ± 0.61 | +5.98 ± 0.74 |
| 同上续训 200 轮 | 600 | +5.39 ± 0.66 | +3.43 ± 0.82 |
| 机器人课程 `--rule-prob 0.50 --league 0.15` | 600 | **+11.52 ± 0.67** | **−0.04 ± 0.68** |

单位是筹码/手，`±` 是标准误；100BB 口径下换算成 bb/100 就是 ×50。
**这张表全部是 100BB + 3-bet 封顶的旧口径**，横向对比（哪组强）仍然有效，
但绝对值换到 ACPC 口径要整体乘 2：旧口径的 −8.08 在新口径是 −1193.6。

只看第一列，课程组是自对局的两倍还多（+576 对 +269 bb/100）。第二列直接把它否了：
**打随机策略是 −0.04，和未训练一模一样。** 未训练的"≈0"是必然的——两边都是均匀随机，
零和对称。所以课程组的第二列说明它**一点通用牌力都没学到**，只学会了怎么打这个特定的
规则机器人。

**单一基准是可以刷的。** 只要"小盲几乎总是加注"，vs 规则机器人就能推到 +11.5，因为
机器人面对加注的应对完全可预测。这不是把牌打好了，是把指标打好了。后面任何"提升"都要
两个基准一起看。

### 自对局为什么不单调（旧口径）

seed 11 那次 400 轮长跑，8 次评估：

```
轮数     50     100     150     200     250     300     350     400
vs规则  -0.98  -0.37  +0.75  +1.48  -4.17  +3.61  +0.21  +2.15
```

±1.8 是标准误，两次评估之差的标准误约 2.5，−4.17 和 +3.61 之间隔了 3 个 σ——
**是真的换了个策略，不是噪声**。

再跑三个种子各 150 轮（同超参、同代码），全部在 50→150 轮之间退化：

| 种子 | 50 轮 | 100 轮 | 150 轮 |
|---|---|---|---|
| 21 | −0.85 | −7.18 | −4.70 |
| 22 | +0.80 | −4.32 | −10.00 |
| 23 | −1.72 | −4.68 | −4.02 |

150 轮时跨了 11 个筹码/手，**150 轮以内的单种子结论没有意义**。

上面那张长跑表每一行也都只有一个种子（自对局组 seed 11 起、seed 32 续；课程组 seed 31
起、seed 32 续）。它证明的是"这套配置能学到东西"，不是"这套配置稳定在 +5.39"。唯一
多子种重复过的是 150 轮那一档，而那一档是负的。

自对局还会短暂塌缩：自对局组续训到第 300 轮时 `jam% 25.2`、熵 0.62（"见牌就全下"），
第 400 轮自己爬回来了。这种瞬时塌缩在日志里只占一行，很容易漏掉——所以看 `jam%` 和
`熵` 比看 loss 有用。

### 两级池 + 三锚点：把振荡压下去（旧口径）

旧联赛的两个毛病都改了——每座位独立抽 → **按局分配**（不再有空转局），单层滚动池 →
**两级池**，并加进规则机器人 0.15 / 随机 0.05 两个风格不同的锚点。

三种子各 300 轮，每 50 轮一档：

```
seed 11   rule   -7.31   -0.46   +1.39   +2.77   +4.24   +5.33
          rand  +15.53  +10.66  +13.29  +10.72  +12.36   +6.62
seed 21   rule   -5.78   -8.66   -3.17   -0.94   +1.30   +1.22
          rand   +9.03  +10.56   +3.13   +7.20   +9.09   +4.91
seed 22   rule   -4.58   -6.19   -2.13   -0.51   +1.11   +0.11
          rand  +12.37   +8.52   +2.74  +11.32  +10.62   +6.35
```

三个种子从第 100 轮起**全部单调往上**，没有再出现旧联赛那种 −4.17 → +3.61 的翻覆。
终点用 8000 手复核：

| 种子 | vs 规则机器人 | vs 随机 |
|---|---|---|
| 11 | +2.62 ± 0.64 | +9.49 ± 0.63 |
| 21 | −0.10 ± 0.55 | +5.02 ± 0.62 |
| 22 | +1.70 ± 0.58 | +8.17 ± 0.70 |

跨种子的 `vs 规则机器人` 落在 −0.10 ~ +2.62（跨度 2.7 筹码/手）；旧联赛同一批种子在
150 轮是 −4.02 ~ −10.00（跨度 6.0）。**方差压下来了一半以上。**

`vs 随机` 的变化更能说明锚点的作用：旧模型是 +3.4 ~ +6.0，新联赛 +5.0 ~ +9.5。随机策略
进了池子，模型才第一次学会"对手无脑全下时该怎么接"——这是只对着规则机器人练不出来的。

但别把这条读成"变强了"：300 轮的均值 +1.4 和旧联赛 600 轮的 +5.39 不能直接比。这一轮
改的是**方差**，不是**上限**。网络仍然没学会看牌，下一节。

### 网络到底有没有在看牌

`probe` 打印同一批局面上各动作的平均概率。三个模型的翻前（小盲先行动）对比：

```
自对局 400 轮                                  机器人课程 600 轮
AA   fold=0.11 call=0.15 r4=0.17 r5=0.16 ...   AA   fold=0.01 call=0.02 r4=0.24 r5=0.24 ...
KK   fold=0.13 call=0.18 r4=0.19 r5=0.16 ...   KK   fold=0.01 call=0.02 r4=0.25 r5=0.25 ...
AKs  fold=0.10 call=0.14 r4=0.17 r5=0.17 ...   AKs  fold=0.02 call=0.03 r4=0.25 r5=0.25 ...
72o  fold=0.18 call=0.21 r4=0.19 r5=0.16 ...   72o  fold=0.03 call=0.04 r4=0.27 r5=0.24 ...

两级池 + 三锚点 300 轮（seed 11，旧口径；r4…r11 是 100BB 下的绝对加注尺寸）
AA   fold=0.02 call=0.03 r4=0.10 r5=0.12 r6=0.15 r8=0.22 r11=0.36 jam200=0.00
KK   fold=0.02 call=0.03 r4=0.10 r5=0.12 r6=0.15 r8=0.22 r11=0.36 jam200=0.00
AKs  fold=0.02 call=0.03 r4=0.10 r5=0.12 r6=0.15 r8=0.22 r11=0.36 jam200=0.00
72o  fold=0.02 call=0.03 r4=0.10 r5=0.12 r6=0.15 r8=0.22 r11=0.36 jam200=0.00
```

`str` 是节点里的牌力特征（翻前 169 类胜率），`eq` 是开天眼胜率。

- 自对局 400 轮：AA 和 72o 的弃牌率 0.11 对 0.18，有分化，但只有 7 个百分点；
- 机器人课程 600 轮：0.01 对 0.03，几乎没有分化；
- **两级池 + 三锚点 300 轮：四行逐位相同**（0.02 / 0.03 / 0.10 / 0.12 / 0.15 / 0.22 / 0.36）。

最后这个是本轮最该记住的负面结果：**新联赛把方差压下去了，牌力区分度却更差了。**
策略现在是一个彻头彻尾的固定模式——"小盲一律弃 2%、跟 3%、按 5.5 倍加注"——和底牌
完全无关。它能赢规则机器人 +2.6 筹码/手，靠的是这个下注尺度本身，不是手里的牌。

`sanity` 证明过链路能学牌（合成优势下 AA 弃牌 2%、加注 62%，85o 弃牌 41%），
所以这里是**信号强度**问题，不是 bug：一手牌的回报标准差约 0.5（已归一化），
"选对动作"的贡献比"牌运"小一个量级，二十万手摊下来动作的功劳被淹掉了。
联赛结构改的是"对手分布"，改不了这个信噪比。

**换成 ACPC 口径（200BB、11.5 万手）之后，这个病一点没好转：**

```
$ ./perfecttexas probe --resume /tmp/ck_acpc300

  KK 翻牌前(先行动)  [str=0.82 eq=0.85] fold=0.10 call=0.14 r220=0.25 r250=0.22 r300=0.16 r400=0.09 r550=0.04
  AKs 翻牌前(先行动) [str=0.68 eq=0.72] fold=0.10 call=0.14 r220=0.25 r250=0.22 r300=0.16 r400=0.09 r550=0.04
  72o 翻牌前(先行动) [str=0.34 eq=0.31] fold=0.10 call=0.14 r220=0.25 r250=0.22 r300=0.16 r400=0.09 r550=0.04
  AA 在 K72 面(先行动) [str=0.92 eq=0.83] fold=0.10 call=0.14 ...
  72o 在 K72 面(先行动) [str=0.93 eq=0.95] fold=0.10 call=0.14 ...
```

六行**逐位相同**，包括最后一行：72o 在 K72 面上是两对，`str` 0.93 比 AA 的 0.92 还高、
`eq` 0.95 对 0.83，而策略输出一模一样。**网络对牌力毫无反应。**

它的翻前策略现在是一句固定台词：弃 10%、跟 14%、2.2 倍加注 25%、2.5 倍 22%…
——不管手里是什么。这就解释了上一节为什么"赢了随机、输给规则、还不如弃牌"：
**能赢随机是因为"不弃牌"本身就够赢随机；输给规则是因为 72o 也照打不误。**

顺带把"输在哪"说清楚：`fold=0.10` 意味着它在小盲位把 72o 也放进 90% 的范围里加注。
200BB 深筹码下这是纯送——翻后要么被更好的牌跟到底，要么自己弃掉已经投进去的 2.2BB。

### 吞吐

单线程 CPU、384 局/轮、hidden 256 / LSTM 128：

| | 旧口径 100BB | 新口径 200BB（ACPC） |
|---|---|---|
| 采样 + 训练 | ~0.6 轮/s（≈230 手/s） | **~0.50 轮/s（≈192 手/s）** |
| 其中采样 | ~55%（含每决策一次开天眼胜率，按街缓存） | 同 |
| 其中 PPO | ~45%（12 个 epoch × 约 3 个 minibatch） | 同 |
| 内存 | 峰值 RSS 约 260 MB | **峰值 RSS 约 211 MB**（池子未满时） |

200BB 比 100BB 慢 17%：无加注上限 + 深筹码，每手牌平均 4.13 个决策（旧 3.97）、
更多牌打到摊牌，加注阶梯每层都是"上次加注额 × 倍数"，动作条数也更多。

`--threads 1` 比默认多线程快约 20%：batch 很小（128），LibTorch 线程池的同步开销
比省下来的算力更贵。

**联赛配比几乎不影响吞吐**：纯自对局 0.57 轮/s，全联赛（自 0.50 / 历史 0.30 / 规则 0.15 /
随机 0.05）0.60 轮/s（均为旧口径实测）。按局分配把每个座位的批次拆成"最新 + 每个快照
各一批 + 规则 + 随机"，forward 次数变多、每批更小；但规则和随机这两种对手不做神经
网络前向，省下来的刚好抵掉。

内存随池子里的快照数线性长：每份快照存 2 个 actor 副本，`--recent 8 --archive 16`
最多 24 份 ≈ 48 个副本，这是旧口径 260 MB 那个数的来源。

## 六、当前状态与已知问题

**能做到的**：规则引擎、特征、动作抽象、自对局采样、PPO、完美信息蒸馏、**两级历史池 +
三锚点联赛**（自对局 / 历史 / 规则 / 随机，按局分配，每局必有一个学习座位）、课程
（`--rule-prob`）、存盘 / 续训、四个诊断工具（`bench` / `sanity` / `critfit` / `probe`）
都跑通了，209 条断言全过。

**规则已经对齐 ACPC：200BB、每街加注次数无上限、下注金额是任意整数**（单个决策点上
合法整数金额覆盖率实测 100%）。按这个口径跑 11.5 万手，策略在学（口径 C：vs 规则
−1828 → −244 bb/100，缩小 7.5 倍），**但仍然是负的**，而且比"永远弃牌"（−75 bb/100）
还差 3 倍。旧口径（100BB、3-bet 封顶）下 300 轮能到 +1.4 筹码/手，但那是浅筹码 +
封顶加注 + 5 个固定尺寸三件事共同作用的结果，不能算到现在的账上。

放开成任意金额**没有**让策略变强：11.5 万手内，5 档尺寸与任意金额的成绩差 0.8σ，
分辨不出来。

**做不到的**：

1. **没学会看牌。** 这是最根本的一条，而且改联赛、改规则口径、放开金额都没有改善它。
   口径 C（任意金额）11.5 万手的 `probe` 里，六个局面（AA / KK / AKs / 72o / K72 面上的
   AA 和 72o）的输出要到第 2~3 位小数才分开（`b300-399` AA 0.13 对 72o 0.12）。
   翻前把 72o 也放进 90% 的范围里加注。`sanity` 证明链路能学牌（合成优势下 AA 弃 3%、
   72o 弃 34%），所以不是 bug，是信噪比。
2. **单一基准会被刷（已部分修复）。** 把机器人曝光拉到 0.5，vs 规则机器人能到
   +11.52（+576 bb/100），但 vs 随机是 −0.04，等于未训练。现在池子里固定有随机和
   规则两种风格，训练日志每次都同时报三个基准——但这是个得长期防的坑，
   不是一次修完的。
3. **单种子仍然只够参考。** 两级池把 150 轮的跨度从 6.0 压到 2.7 筹码/手，
   但三个种子在 300 轮仍分布在 −0.10 ~ +2.62。报结论至少三种子。
4. **绝对强度没标定。** 没有 CFR 均衡基准，"vs 规则 +2.6"只说明"比这个启发式强"，
   不说明接近均衡，更不说明能打赢人。
5. **"实时对齐"只是同步更新，不是同分布。** 采样用的价值网与更新后的价值网差一轮，
   GAE 用的是旧值。这对 PPO 是标准做法，但和 PerfectDou 的异步 buffer 不一样，
   没有做重要性修正。
6. **开天眼胜率是抽样。** 转牌 / 河牌精确枚举（44 / 1 种），翻牌前与翻牌用 32 次抽样，
   标准差约 4~9 个百分点。进特征没问题，当势函数会带来奖励噪声。
7. **会短暂塌缩。** 观测到一次 `jam% 25%` + 熵 0.62 又自己恢复；也观测过更严重的
   "从不弃牌"（摊牌率 44% → 80%，见第二节 Φ 的踩坑记录）。抑制手段是熵系数 0.02 +
   critic 额外 8 个 epoch + 两级池，都只是缓解。
8. **单线程采样。** 每个线程要一份独立的模型副本（`cloneActor`），暂时没做；
   当前吞吐瓶颈是采样里的前向和每决策一次的开天眼胜率。
9. **内存随池子涨。** `recent 8 + archive 16` 最多 24 个快照 × 2 座位 = 48 份网络副本，
   旧口径满池实测 260 MB，新口径池子未满时 211 MB。
10. **大小盲两套行为不自洽。** `evalSelfPlay` 报的 `self` 列测的是座位 0（小盲）的收益，
    零和下它和座位 1 必然互为相反数，所以这一列读的是"网络自己的小盲被自己的大盲
    打得多惨"：三次评估 +107.6 → −423.7 → +110.8。−423.7 那次是 3σ，不是噪声。
    可疑点在特征：节点特征是"我/对手"视角（`me = s.toAct`），而历史序列的座位位是
    绝对座位（`features.cpp` 里 `t[0] = (e.seat == 0)`），网络要自己学这个换算。
    改成相对视角是一次干净的消融实验，但会让所有旧 checkpoint 语义失效（维度不变，
    加载不报错、结果全错），所以没动。
11. **200BB 下样本量不够。** 训练后模型 σ ≈ 49.5 BB/手，要 ±10 bb/100 的分辨率需要
    25 万手，±5 需要 100 万手。现在跑的是 11.5 万手，只能分辨 ±30 bb/100 以上的差异。

**下一步优先级**（按性价比重排过）：

1. **对着第 1 条病根去**：牌力区分度。这条已经被证明不是联赛结构、也不是规则口径
   的问题。可行的方向是把"动作功劳"从"牌运"里更彻底地剥出来——除了
   `R − V_开天眼(s)`，再加一层"同牌不同动作"的配对采样（同一副牌、同一张公共牌，
   只换动作，直接估 ΔR），用配对差把方差压掉一个量级。这也是第 11 条（样本量）的
   唯一可行解：200BB 下靠加手数要 100 万手，靠配对差可能只要十万手。
2. 多线程采样 + 线程私有模型副本（预期 4~6 倍吞吐），同样的墙钟时间换样本量。
3. 采样端只收集 (s, a, logp, R)，价值网用独立回放缓冲多跑几轮，解决第 5 条。
4. 动作抽象再压一档做对照（现在是 5 档尺寸；旧 CFR 版本的实验说明"档数"是主要杠杆）。

## 八、教师蒸馏：让网络学会看牌（2026-10-26）

### 问题：PPO 的优势里，"发牌运气"比"动作功劳"大一个量级

旧版的病根在第五节已经写死：**probe 里 AA / KK / AKs / 72o 的输出逐位相同**，
网络完全没有看牌。`sanity` 把优势换成合成信号后能学会（AA 弃 2%、85o 弃 41%），
所以 actor / PPO / 特征 / 动作映射这条链路是通的；**真实训练里动作的贡献被
终局回报的发牌方差淹掉了**。200BB 下要 ±10 bb/100 的分辨率需要 25 万手，
靠加样本量不现实。

### 方法：同牌分支续演 + 隐藏牌平均 + 交叉熵蒸馏

每个学习决策点先枚举全部合法动作，然后**用同一副牌（同一对手底牌、同一公共牌）
把每个动作分别续演到终局**，得到一个动作价值 Q：

```
Q(s, a) = payoff( 执行 a 后，双方都按脚本教师打到底 ) / 起始筹码
```

分支之间只差我们的动作，公共牌在开局一次发定（`applyMove` 不再抽牌），
所以 **Q 的动作间差异里没有发牌方差**，这正是 PPO 缺的那个信号。

三个关键细节：

1. **隐藏牌平均。** actor 看不到对手底牌。如果只对"这一手具体对手牌"蒸馏，
   隐藏牌一换最优动作就会翻转，网络学到的会是"一半全下、一半弃牌"的混合。
   所以 `--teacher-samples 8` 会对**信息集里看不见的牌**（对手底牌 + 未发公共牌）
   重新采样 8 次，取平均 Q，再做 softmax。
2. **逐状态标准化。** 动作选择只取决于同一局面内 Q 的相对大小；绝对筹码尺度
   会把每个目标都压成"接近均匀"。学习器里对合法动作做 `(Q−均值)/标准差`，
   温度 0.5 才成为一个有意义的旋钮。
3. **只灌 actor，不进 PPO 优势。** 教师损失是 `CE(softmax(Q/T), π)`，
   和 PPO 的 `A = R − V_开天眼` 分开。教师偏差不会污染价值基线。

教师默认有三种续演风格，取平均：紧弱 / 标准 / 松凶的规则机器人。
`--teacher-styles 4` 会再加一条**翻前胜率机器人**（翻前用 169 类表，所以很便宜；
翻后回落到标准规则），让 Q 见过"3BB 开场 / 按胜率防守"的节奏。
v4 做了这条消融：教师目标的熵从 1.15 涨到 1.34、top-1 从 0.56 掉到 0.49，
前 50 轮 vs 胜率一度掉到 −385，但 200 轮后升到 **+406 ±62**（v3 是 +232），
代价是 vs 规则从 +1251 掉到 +1091、vs 随机从 +1823 掉到 +1478。
所以这条不是"更好"，而是**把策略重心从规则机器人挪到胜率机器人**；
默认仍是 3 种，v4 是 4 种的可行配置。

**翻前永远标注，翻后按 `--teacher-prob` 抽样**：翻前范围是旧策略最大的漏洞，
而且翻前教师的分支续演已经评估了翻后；翻后标注贵一个量级，默认只抽 25%。

### 教师回放：把"每轮只看一眼"变成多看几眼

`distill` 的诊断说得很清楚：固定 907 条样本上跑 400 步，KL 能从 0.58 压到 0.14；
在线训练每轮却只有约 1000 条新样本、24 个梯度步，所以同样 400 轮只能到 0.4。
`--teacher-replay 2048` 把最近 2048 条/座位的教师标注（node / seq / Q / 动作特征）
缓存下来，每轮在回放上额外跑 `--teacher-replay-steps 1` 组纯蒸馏，
系数是 `teacherCoef × teacher-replay-coef`（默认 0.5）。

- 回放样本的 Q 是**固定的价值目标**，不依赖当时的策略，所以 off-policy 蒸馏是合法的；
- 日志新增 `rce`（回放 CE）。它通常比在线 `tea` 高，因为回放里混着更老的、
  更难的状态；随着缓冲区填满会下降；
- 成本：2048 条/座位约 15 MB，每轮多 16 个 minibatch，吞吐从约 0.65 掉到 0.54 轮/s。
- v6 把它灌进已经很强的 v4，结果 pro 从 +406 掉到 +150——回放不是"补课"工具。
  从零开始的 A/B（v7 replay vs v7 noreplay）用来隔离回放本身的效果。

### 配套修正：牌力抽象真的看见听牌了

`strength.hpp` 的注释一直写着"用 outs 对百分位做期望修正"，但 `handStrength`
实际只返回"当前最佳五张的排名"——花听/顺听会被当成空气牌。现在补上了：

```
p_hit = 1 − C(未见−outs, 2)/C(未见, 2)   （翻牌，两张到来）
p_hit = outs / 未见                      （转牌，一张到来）
eff   = (1−p_hit)·百分位 + p_hit·命中后百分位   （花 0.94 / 顺 0.89）
```

这条同时改善了**特征 `x[14]`** 和**规则机器人**（它以前会弃掉花听）。
所以 2026-10-26 之后的数字统一是"新牌力口径"，和第五节旧口径不能直接比。

### 评估：同牌对调 + 两个检查点对打

旧 `eval` 两遍用不同发牌，8000 局的标准误约 ±118 bb/100。现在两遍用**同一批发牌**、
只换座位（duplicate match），每个配对样本是"模型在一边拿强牌、另一边拿弱牌"的
两局收益和。8000 局的标准误降到 **±67**，同样的手数分辨率提高近一倍。

新增工具：

| 命令 | 用途 |
|---|---|
| `eval --vs pro` | 对**胜率机器人**（对随机手牌 MC 胜率，比规则机器人风格更接近真实） |
| `eval --vs search` | 对**搜索机器人**（隐藏牌平均后的教师 Q argmax，每一步都做同牌分支续演） |
| `eval --vs mix` | 对**混合基准**（规则 .25 / 胜率 .35 / 搜索 .30 / 随机 .10，座位随机） |
| `match --a DIR --b DIR` | 两个检查点同牌对调对打，直接回答"新版有没有比旧版强" |
| `soup --a DIR --b DIR --out DIR --alpha F` | 同架构检查点参数平均（model soup），事后免费提升 |
| `botmatch --a pro --b search` | 任意两个机器人对打，用来标定基准之间的强弱 |
| `distill` | 固定一批带教师标注的样本，只跑蒸馏损失，隔离"优化链路"和"信号" |

### 检查点平均（model soup）：最便宜的一次提升

`perfecttexas soup --a DIR --b DIR --out DIR --alpha 0.3` 把两个同结构 actor 的
参数按 alpha 线性插值（critic 从 a 复制）。这不是训练，但它是训练流程里最便宜
的一步：几个秒级命令，换掉一场 200 轮的训练。

| soup | 混合均值（3 seeds） | 单挑 / 备注 |
|---|---|---|
| v9b + v9d 50/50 | +825 | 赢 v9b +143 ±55、赢 v4 +185 ±57 |
| **v9b 30% + v9d 70%** | **+889** | 赢 v9b +104 ±59、v9d +30 ±50、v4 +80 ±56 |
| v9b 70% + v9d 30% | +792 | — |
| v9b + v9d + v10a（1/3 each） | +836 | — |
| v9b + v9d + v9c（1/3 each） | +887 | — |

**30/70 的 soup 就是 `ckpt_v12`**：rule +1746 ±81、pro +584（两 seed）、
search +402（两 seed）、random +1190 ±86，最差基准（搜索）也略好于 v4 的 +392。
单挑对 v9b/v9d/v4 全为正，虽然幅度不大（+30~+104）。

alpha 网格（alpha = v9b 的权重，mix 三个种子均值）：
`0.10 → 798 / 0.20 → 765 / 0.25 → 797 / 0.30 → 889 / 0.35 → 802 /
0.40 → 853 / 0.50 → 891 / 0.70 → 877`。
0.30 和 0.50 在噪声内打平，选 0.30 是因为它的 pro/search 两个种子均值更高
（+584 / +402 对 +537 / +372）。再拿 v12 去混 v10a（30%）或 v9c（30%），
mix 均值只有 830 / 826，没有超过 v12，所以停在这里。

为什么有效：几个模型都是不同 exploit 的组合，参数平均会把过度极端的
下注边界抹平一些；它不保证单调，但在这里同时抬高了 mix 和最差基准。
**限制**：只能平均同架构、同特征口径的检查点；它是"事后优化"，
不能替代冷启动训练；平均后的 critic 未必准，所以只用于评估/对局，
不用于继续训练。

v3 的联赛配比是：自对局 0.40 / 历史 0.25 / 规则 0.10 / 随机 0.05 / **胜率 0.20**；
教师系数 0.2，前 100 轮线性退火到 0。probe 显示它仍然看牌（AA 的大注 ≥800 占 25%，
72o 只有 11%；AA 弃牌 7% 对 72o 14%），但没有 v2 终版那么极端。

### 诊断与失败记录

- **蒸馏链路本身没问题。** `distill` 固定 907 条样本（766 条带教师标注），
  只跑教师损失：CE 1.768 → 1.332，目标熵 H=1.188，**KL 0.580 → 0.144**（400 步）。
  在线训练每轮只有约 1000 条新样本、24 个梯度步，所以同样 400 轮只能把 KL 压到
  0.4 左右——**瓶颈是"每轮看多少眼教师"，不是梯度坏了**。
- **教师必须退火，常驻会伤 generalization。** 同一份 v2 终版续训 300 轮：
  教师 0.2 常驻 → vs 胜率 −461、单挑输给 v2 终版 −267；
  教师 0.2 前 100 轮退火 → vs 胜率 −147、单挑赢 v2 终版 +365。
  教师是"规则机器人风格"的专家，常驻会把策略钉在这个风格上。
- **胜率机器人证明了"单一基准可以刷"。** v2 终版 vs 规则 +540，但 vs 胜率 **−445**。
  胜率机器人对规则机器人只赢 +53 ±38，风格却完全不同——**非传递性**是扑克的常态，
  任何"我们变强了"都必须报一组基准 + 单挑，不能只看一个数。
- **v3 和 anneal 单挑只是打平**（−6 ±70），尽管 v3 在三个基准上全面更好。
  这说明基准分和单挑强度不是一回事；目前没有"全面支配"的策略，只有不同的 exploit。
- **PPO 仍会振荡。** v3 训练中 vs 胜率在 +267 / −79 之间跳（每 50 轮一次评估，
  SE 约 90），`self` 也在 −447 ~ +269 之间。教师退火能降低振幅，但没有消除。
- **critic 还是弱。** 训练日志 `val ±` 和 `c`（价值预测与回报的相关系数）只到
  0.1~0.3；`val` 的标准差约 0.4，回报约 0.7。所以 PPO 那一半的信号仍然有限，
  教师退火后的提升主要来自"联赛多样性 + 自对局"，不是 critic 突然变准了。
- **教师 Q 仍然是脚本的 Q。** 它衡量的是"按脚本打到底"的价值，不是均衡价值。
  对胜率机器人/规则机器人有效，不等于接近 CFR 的可利用度下界。
- **把搜索机器人塞进联赛没有自动提高搜索基准。** v5（v4 再 200 轮，search 0.20）：
  rule +1364、pro +384、search **+138**、random **+844**；单挑 v4 +73 ±56（不显著）。
  搜索基准从 v4 的 +392 掉到 +138、随机从 +1478 掉到 +844。两个原因：
  训练用的 8 样本搜索和评估用的 16 样本搜索不是同一个强度；随机只占 5%，
  被 20% 的搜索挤掉了。结论：**锚点进联赛必须同时匹配评估强度、并保住弱锚点的采样比例**，
  不能只看"加了更多对手"。
- **按最差基准选 checkpoint，而不是按单挑。** v5 单挑略胜 v4（+73 ±56），
  但最差基准从 v4 的 +392（搜索）掉到 +138。当前仍以 v4 为主力；
  v5 保留作"联赛加搜索"的失败对照。
- **教师回放不能直接灌进一个已经很强的模型。** v6（v4 续训 200 轮 + 回放 2048）：
  rule +1022、pro **+150**、search +271、random +1294；单挑输给 v4 −70 ±58。
  起初 pro 一度掉到 −814，后来爬回 +150，但始终没恢复到 v4 的 +406。
  原因和"教师常驻"一样：回放里的 Q 是脚本教师的价值观，对一个已经适应
  胜率/搜索风格的策略是**反向拉力**。回放应该用在**冷启动**阶段，
  而不是拿来给强模型"补课"。
- **冷启动的课程顺序比回放本身更重要。** v7 从零开始，教师 0.5 前 200 轮退火，
  胜率机器人从第一轮就占 0.20。A/B（同种子、同超参）：
  replay 到 300 轮是 rule +690 / pro +164 / random +1101；
  noreplay 是 rule +344 / pro +90 / random +464。
  **回放确实明显优于控制组**，但两条都远低于 v2→v3→v4 这条"先把规则/自对局打稳、
  再把强锚点加进来"的课程。结论：回放要用在冷启动的**规则/自对局阶段**；
  强锚点不能从第一轮就压 20%。
- **可利用度探针：PPO best response 没有明显打穿 v4。**
  `--freeze-opponent ckpt_v4`（每局随机座位，关掉联赛）跑 150 轮：
  BR 对 v4 **+79 ±56**（1.4σ，不显著）；BR 自己 vs rule +668、vs pro −103、
  vs search +245。这是弱证据——PPO 不是精确 best response，150 轮也不一定收敛；
  但它至少没有像 v2 那样被单一基准打成 −445。
- **v8 冷启动两阶段的第一阶段不够长。** 从零开始、教师 0.5 + 回放 2048、
  胜率机器人只占 5%，跑 200 轮（未配对训练日志）：rule +254、pro −952、random +1516。
  这个底子明显弱于 v2 路径（400 轮 +516 vs 旧规则），再花 200 轮加强锚点也追不上，
  所以没有跑第二阶段。教训：**回放/冷启动要给够轮数**，不能把 200 轮当成 400 轮用。

### 2026-10-26 下午：集成 / 价值 / 搜索 / 更强教师 / BR 的系统性失败记录

这一轮把"能不能不重训就变强"的几条路都试了一遍。结论先说：**全部没有超过 v12**。
留下记录，避免以后再走一遍。

**1) 动作级集成（`--ensemble`，新功能）。** 每个座位多套 actor，各自前向，
把 masked softmax 的**概率**平均后采样（和参数平均的 soup 不同，不要求同一盆地）。
8000 手、seed 90001：

| 团队 | mix | 单挑 vs v12 |
|---|---|---|
| v12 | **+833 ±96** | — |
| v12 + v10a | +771 | −47 ±35 |
| v12 + v9c | +685 | — |
| v12 + v10a + v9c | +681 | −8 ±36 |
| v12 + v9a | — | −45 ±34 |
| v12 + v9b | — | −31 ±37 |

唯一亮点是 v12 + v10a 对搜索基准 +430（v12 同种子 +355），但它的 mix 和单挑都退步。
**等权概率平均会把 v12 的 exploit 性抹平**；集成成员都比 v12 弱，平均只会向它们靠。
同权重克隆当成员时结果逐位相同（测试钉住了这条恒等性），所以不是实现问题。

**2) critic 的真实问题是过拟合，不是容量。** `critfit` 现在支持 `--resume` 和
8:2 留出集。716 条自对局样本、从 v12 的价值网开始：

| 配置 | 训练 RMSE | 留出 RMSE | 留出相关 |
|---|---|---|---|
| 无正则，1500 步 | 0.1713 | 0.3410 | 0.424 |
| wd=1e-3，1500 步 | **0.1133** | **0.2014** | **0.850** |
| wd=1e-2，1500 步 | 0.2232 | 0.2214 | 0.803 |

回报标准差是 0.3418，所以无正则时留出集 R²≈0——**网络把 716 条样本背下来了**。
加 L2 后 R²≈0.65，说明结构和特征都够用，瓶颈是每轮只有约 2000 条样本的在线过拟合。
新增 `--critic-weight-decay`。但线上 `c` 没有明显改善（150 轮 A/B：0.28/0.48 对
0.33/0.37），mix 均值 693（wd=0，2 seeds）对 751（wd=1e-3，4 seeds），都在 ±100 噪声内，
且所有新检查点单挑都输 v12（−5 ±31 / −51 ±38）。

**3) 价值回放（`--critic-replay`，新功能）没有用。** 8192 条/座位、每轮 2 epoch：
vLoss 从 0.07 降到 0.04，但 `c` 不升，训练速度从 0.75 掉到 0.39 轮/s。收益是"拟合旧回报"，
不是"更会泛化"。默认关闭。

**4) 策略内搜索（`--policy-search` / `--search-a`，新功能）不能当改进算子。**
它枚举每个合法动作，用同一批隐藏牌分支、双方都按当前策略续演到底，取平均回报最大者。
v12 自己对自己（8000 手，seed 24680）：**search-4 −667 ±85、search-8 −394 ±85**。
样本越多越好，但 8 个样本时每动作 Q 的噪声仍有 ~0.3BB，而动作之间的真实差常常只有
0.02~0.05BB；argmax 的最大化偏差会把策略推向"在这几副抽样牌上看起来最好"的动作。
**没有足够样本或可靠价值网时，MC 搜索是负向算子**，不是免费的策略改进。

**5) 更强的教师反而更差。** teacher-samples 8→16、styles 3→4、加 critic wd，
从 v4 跑 120 轮（同种子 7201/7202）：

| 配方 | mix（2 seeds） |
|---|---|
| 8 样本 / 3 风格（v9 口径） | +787 / +775 |
| 16 样本 / 4 风格 + wd | +735 / +606 |

教师 Q 越准，越把策略钉在"规则机器人续演"的价值观上。**教师是风格专家，不是均衡解**；
维持 8 样本 / 3 风格 / 前 100 轮退火。

**6) BR 打不穿 v12。** 关掉联赛、每局随机座位冻结 v12，训 150 轮（无教师）：

| BR | 单挑 vs v12 | mix |
|---|---|---|
| br_a（从 v12 续训） | −101 ±40 | +558 |
| br_b（从 v12 续训） | **+70 ±41**（seed 24680）/ −19 ±41（seed 13579） | +706 |
| br_c（从 v4 起） | +3 ±38 | +342 |

br_b 在第二个发牌种子上不复现，合并约 +25 ±29（不显著）。把 br_b 与 v12 soup
（alpha=0.5/0.7/0.85）：单挑 +1 ±38 / +2 ±38 / −9 ±38，mix 740 / 796 / 779。
**BR 只能找到 v12 的弱点，找不到更强的策略**——这正是"非传递性"的又一组证据。

**7) 本轮 soup 网格没有新王。** v12 在 seed 90001/90002/90003 的 mix 是
+833 / +806 / +760（均值 800）。拿本轮最好的两个 wd 检查点（s2 均值 846、s3 均值 809）
与 v12 soup：

| soup | mix（2 seeds） | 单挑 vs v12 |
|---|---|---|
| v12 + s2 50/50 | +854 | −22 ±36 |
| v12 + s2 70/30 | +846 | −35 ±36 |
| v12 + s2 85/15 | +764 | −68 ±36 |
| v12 + s3 70/30 | +842 | −24 ±38 |
| v12 + s2 + s3（各 1/3） | +788 | −29 ±38 |

没有一个候选在 mix 和单挑上同时超过 v12。**soup 的红利在 v12 这里已经吃完了。**

**8) 长程训练：不退化，但也不超过 v12。** 从 v9b 继续 600 轮纯 PPO（教师已关，
lr 5e-4，联赛同 v9，只有 critic 正则不同，同 seed 9001）：

| 长程 600 轮 | mix（2 seeds） | 单挑 vs v12 |
|---|---|---|
| critic wd=0 | +673 / +730（均值 701） | −21 ±40 |
| critic wd=1e-3 | **+820 / +838（均值 829）** | −36 ±42 |

两个模型都没有超过 v12（同两个种子均值 820），但 **wd=1e-3 在同起点、同种子的
600 轮里比 wd=0 高 128**——这是本轮唯一一个方向明确、幅度也够大的正则收益。
长程训练本身不会让策略崩掉（600 轮后仍在 v12 水平附近），但也没有继续变强：
**v12 已经是这条训练曲线的一个局部平台。** 把 long_wd1e3 与 v12 soup（50/50、70/30）：
mix +584/+562 与 +682/+691，单挑 +0 ±33 / +13 ±33 与 +66 ±33 / −25 ±33。
50/50 甚至把 mix 打掉约 250，**两个走势相近但风格不同的模型做参数平均，
会把 v12 的 exploit 性抹掉**；这个现象和动作级集成的结果一致。

**9) 分座位看：座位差主要是位置，不是"某一个网络更差"。** 新的 `match` 会同时报
两个座位。v12 自己打自己时，小盲 actor 对 v12 大盲在两组发牌上是 −131 / −24 —
这是位置的必然（小盲先动、翻后没位置），不能读成"小盲网络更弱"。不过按座位
拼装（小盲/大盲取不同检查点）仍然值得试，结果是**也没有更好的组合**：

| 组合 | mix（2 seeds） | 单挑 vs v12（2 seeds 合并） |
|---|---|---|
| v12 小盲 + long_wd1e3 大盲 | +857 / +773 | −17 ±28 |
| br_b 小盲 + long_wd1e3 大盲 | — / +619 | **+30 ±28** |
| soup(v12,br_b) 小盲 + long_wd1e3 大盲 | +786 / +751 | −24 ±28 |
| soup(v12,br_b) 小盲 + soup(v12,wd) 大盲 | +734 / +633 | −52 ±27 |

`br_b 小盲 + wd 大盲` 是唯一两组种子都为正的单挑组合（+31 / +29），但它的 mix 只有 619。
**这又是一次"单挑 vs 基准"的取舍，而不是全面支配。**

**10) 采样并行：拿不到 3~5 倍，因为瓶颈在学习器。** 新增 `--workers N`（按局切分、
合并时给 gameId 加偏移，GAE 仍按局分组）。384 局/轮：

| 配置 | 轮/s |
|---|---|
| workers=1，torch 单线程 | 0.68~0.70 |
| workers=4，torch 单线程 | 0.71~0.72 |
| workers=1，torch 默认线程（10 核） | 0.54 |
| workers=4，torch 2 线程 | **0.99** |

采样并行本身几乎不涨：`collectRollout` 只占每轮的一小部分，**大头是
`Learner::update` 的前向/反向**（4 个 actor epoch + 12 个 critic epoch）。
想把训练规模真正抬上去，得先把学习器变快（更大 minibatch / GPU-MPS /
减少 critic epoch），否则加采样线程只是把 CPU 空转在等梯度。**采样过来的 gameId
偏移与统计合并已经写好，等学习器提速后可以直接用。**

**11) 把 batch 放大 4 倍（同样总手数）不会更好。** 同一台机器、同样约 23 万手：
600 轮 × 384 局（long_wd1e3）对 150 轮 × 1536 局（bigbatch），都是 wd=1e-3、
lr 5e-4、同 seed：

| 配方 | mix（2 seeds） | 单挑 vs v12（2 seeds） |
|---|---|---|
| 600 × 384 | +820 / +838（均值 829） | −36 ±42 |
| 150 × 1536 | +705 / +842（均值 773） | −8 ±46 / −25 ±48 |

大 batch 的单挑略好、mix 略差，合起来还是打平/略输。**这个训练循环不是被
梯度噪声卡住的**；同样的样本，多轮小 batch 至少不差。这也解释了为什么
`--workers` 的吞吐提升换不来强度：真正缺的是"有效的 critic 更新量"和"更多
不同局面的数据"，不是"每步更准的梯度"。

**这一轮的统一结论**：v12 是一个稳定的局部最优。想再往前走，必须先换一个
明显不同的基座（结构或规模），在 v12 附近做微调、平均、搜索、对抗都只会
在"mix / 单挑 / 搜索基准"之间来回交换，不会产生全面支配的新王。

**12) critic 的"更多步数"和"信息集价值网"都被证伪。** 100 轮 A/B（从 v9b，
seed 8101，teacher 0，wd=1e-3，只改 critic 设置）。`c` 是训练日志里"价值预测
与本批回报"的相关系数：

| critic 设置 | 平均 c | 轮/s |
|---|---|---|
| extra epochs 0 | **0.441** | **0.79** |
| extra epochs 8（默认） | 0.438 | 0.51 |
| extra epochs 4 | 0.411 | — |
| extra epochs 2 | 0.391 | — |
| extra epochs 8 + wd 1e-2 | 0.366 | — |
| extra epochs 32 | 0.357 | 0.27 |
| `--critic-info-set`（只喂 actor 可见特征） | 0.102 | — |

三个结论：

1. **加步数没用**：32 个额外 epoch 反而比 8 个更低（0.357 对 0.438）。它让
   价值网更贴上一批数据，在新一批上泛化更差——和离线诊断里"训练 RMSE 降、
   留出 RMSE 升"是同一件事。
2. **去掉开天眼特征更糟**：c 直接掉到 0.102。开天眼 baseline 不是"偏差"——
   baseline 只要不依赖动作就不改变策略梯度的期望，它只是方差更小；
   信息集版本的条件期望更难估，样本效率反而低。
3. **默认的 8 个额外 epoch 可以降到 0**：c 不变，训练快 1.55 倍
   （0.51 → 0.79 轮/s）。这是本轮唯一可以立刻采用的调参结论。

600 轮长程的同种子直接 A/B（都从 v9b、wd=1e-3、lr 5e-4、其余完全相同）：

| critic extra epochs | 最终 c | mix（2 seeds） | 单挑 vs v12 |
|---|---|---|---|
| 0 | **0.57** | **+917 / +988（均值 952）** | −46 ±46 |
| 8 | 0.28~0.40 | +820 / +838（均值 829） | −36 ±42 |
| 32 | 0.27~0.35 | +641（1 seed） | −14 ±28（T=0.1 对 T=0.1） |

**"多跑 critic"在长程上不是没用，而是有害**：32 个额外 epoch 让 600 轮后的
mix 从 952 掉到 642。默认值应该改成 0。

**13) 部署时把策略变尖（温度 / 贪心）：本轮唯一全面变强的改动。**
新 `eval --temp F` / `--greedy`、`match --a-temp/--a-greedy`。动作是
`probs ∝ softmax(logits / F)`，greedy 直接取 argmax。8000 手 / 16k 手对局：

| 提取方式（ckpt_v12） | mix（3 seeds 均值） | rule | pro | search | random | 单挑 vs v12 采样 |
|---|---|---|---|---|---|---|
| 采样（T=1） | +800 | +1746 | +584 | +355 / +370 | +1190 | — |
| T=0.5 | +973（1 seed） | — | — | — | — | +36 ±32 |
| T=0.25 | +945 | +1987 | +852 | +359 | +1178 | +60 ±23（2 seeds） |
| **T=0.1** | **+956** | **+1986** | **+852** | **+376 / +331** | +1131 | **+82 ±17**（3 seeds） |
| greedy | +952 | +1956 | +886 | +329 | +1111 | +81 ±31 |

**温度 0.1 在 mix 上抬了约 156，单挑赢采样版 4.8 个标准误**（+101/+76/+74，
三个发牌种子）；rule / pro 都涨，search 基本持平（两 seed 均值 354 对 363），
random 掉 59（在 ±54 噪声内）。greedy 的 mix 差不多，但 search 掉到 +329、
单挑也略低，所以选 T=0.1。注意：**尖锐策略对自适应对手更可被利用**，
我们现在的锚点都是固定的；search 基准没有变差是唯一的反证。

这不是新的训练，而是"提取"：网络输出的分布本来偏软（训练时 entropy 系数 0.02），
它的众数比它的采样更强。下一步应该让训练本身产出更尖的分布（entropy 退火到 0），
这样 T=1 就能接近现在 T=0.1 的水平。

**14) 熵退火没有复制这个收益。** 从 v9b 跑 300 轮，`--entropy 0.02 --entropy-final 0`
对固定 0.02（其余相同，extra critic epochs=0）：

| 熵系数 | 最终熵 | mix T=1 | mix T=0.1 |
|---|---|---|---|
| 0.02 → 0 | 0.776 | +666 / +607 | +705 / +610 |
| 0.02 固定 | 1.480 | +517 / +635 | +763 / +795 |

退火确实让 T=1 变好（636 对 576），但 T=0.1 反而更差（657 对 779）——
**它把策略"提前变尖"，牺牲了探索与后续可提取性**。而且两条都远低于 v12
（300 轮还不够）。结论：不要在训练里退火熵；尖策略用评估时的温度提取。
另外这两条也说明 300 轮的中间模型不可信，长程 A/B 至少 600 轮。

**15) 新的最优"智能体"：`ckpt_v12` + T=0.1 提取。** 它不是新 checkpoints，
而是同一个网络的 sharper 提取：mix 三 seed 均值 +956（对采样 +800）、
单挑赢采样 v12 **+82 ±17**（三个发牌种子，4.8σ）、rule +1986 / pro +852 /
search 354 / random +1131。**唯一没有变好的大锚点是 search（持平略降）**，
所以它仍然不解决"对自适应对手的可利用性"这个根本问题——但它是本轮唯一
在四个指标上同时为正、且单挑显著的改动。

**16) 尖策略不是"固定锚点假象"：它反而更难被 BR 打穿。** 新
`train --freeze-opponent DIR --freeze-temp F` 让冻结对手也用部署提取方式。
从 v12 起、同 seed、150 轮、无教师，分别训练两个 BR：

| BR 训练时的目标 | BR 对目标的收益（BR 用 T=0.1） |
|---|---|
| 采样 v12 | +106 ±34 / +77 ±32（合并 **+91 ±23**） |
| T=0.1 v12 | +27 ±22 / +41 ±21（合并 **+34 ±15**） |

尖版本被 BR 打穿的幅度只有采样版的三分之一左右。**"尖 = 更可被利用"在这里
不成立**：训练出来的混合策略不是均衡混合，而是 entropy 正则带来的噪声，
其中包含相当概率的差动作；收紧分布恰好去掉这些送分动作。固定 BR 只能测到
"针对这套提取的可利用性"，真正的自适应对手仍需外部基准验证。

**17) 常数低熵（0.005）训练更差。** 600 轮、同起点同种子：mix +662（T=1）/
+681（T=0.1），远低于 entropy 0.02 的 +952 / +1104。结合第 14 条（退火到 0
也差），**熵系数保持 0.02 是最优的**：探索必须留，尖策略靠评估温度提取。

**18) 共享 actor 不是干净的提升。** 新 `--shared-actor`（SB/BB 共用一套参数，
初始化 = 两座位平均，critic 仍分座位；数据翻倍、参数减半）。从 v9b 起、同 seed
600 轮、critic extra epochs 0 + wd=1e-3：

| 模型 | mix（2 seeds，T=1 / T=0.1） | 单挑 vs v12+T0.1（2 seeds） |
|---|---|---|
| v12 | +800 / +956 | — |
| long_e0（分座位 actor） | +952 / +1104 | =（见第 12 条） |
| shared_600 | +660 / **+730** | +53 ±30 |

共享 actor 的 **mix 明显更低**（730 对 956），但**单挑 vs v12+T0.1 反而赢
+53 ±30**。这是又一次"基准 vs 单挑"的交换：共享后两个座位变成了同一策略，
单挑更稳，但应对混合作弊式锚点（规则/胜率/搜索混合）变差。**没有全面支配**，
依然保留分座位 + v12 作为当前冠军。把它与 v12 soup（50/50、70/30）更差：
mix +513/+594 与 +245/+193，70/30 的单挑也变成 −35 ±7——**跨"共享/分座位"
的参数平均会掉进一个很差的地带**。（注：共享 actor 的 SB/BB 相同网络还是会
写入不同文件，评估时两个座位角色由节点特征决定。）

**19) 接入 Slumbot：第一个真正的外部基准。** 新增 `slumbot` 子命令，用
libcurl 直接打 Slumbot 的公开 API（`/slumbot/api/new_hand`、`/act`）。
它的规则和本引擎**完全一致**：盲注 50/100、起始 20000（200BB）、每手重置；
动作串 `b200c/kb400/...` 的 `b<金额>` 就是本街累计投入额，和 `Move.to` 同口径。
客户端把动作串重建成 `HUState`（自己底牌归到正确座位，对手底牌/未发公共牌
用任意未用牌占位——策略只看得见自己的牌和已发公共牌），再用 `policyMove`
按 T=0.1 提取动作。`buildSlumbotState` 有三条测试钉住：底池/投入/行动权、
全下终局、非法输入拒绝。

对外部对手的结果见下一节（数字填在下面）。

**20) Slumbot 第一轮结果：样本太小，先别下结论。** 每轮 300 手：

| 模型 / 提取 | 300 手净收益（筹码/手） | 每手 σ（估计） |
|---|---|---|
| v12 + T=0.1 | −324.9 | ~5000 |
| v12 + T=1（采样） | −183.8 | ~5000 |
| long_e0 + T=0.1 | +0.3 | ~5000 |

**关键教训：200BB 的全下让每手标准差达到 ~5000 筹码（50BB）**，300 手的
标准误约 **±290 筹码/手**——上面三个数彼此都在 1σ 内，**不能据此说谁更强**。
这也解释了为什么同一配置两次 300 手可以一个 −325、一个 +0.3。

目前唯一能站住的结论：**我们对 Slumbot 没有稳定优势**，点估计在
−3.2BB/手（v12）到 0（long_e0）之间。要把误差压到 ±100，至少需要
~2500 手；压到 ±50 需要 ~10000 手。客户端本身用 `--policy fold` 校验过记账：
20 手永远弃牌净 −60 筹码/手（理论 −75，差额来自 BB 的 walk），动作串重建、
手数统计、winnings 字段都对得上。

**21) Slumbot 客户端加固：并发会被限流，全下可以按胜率调整。**
上一轮两个会话并发跑 `--delay-ms 10`，`act` 频繁返回非 200（每 20~40 手一次）。
被中止的手不计 `winnings`，等于从样本里删掉这些手——如果错误率与牌局长度
相关，就会产生幸存者偏差。改成**串行 + 150ms** 后，120 次请求 0 错误；
60ms 单会话也测过 80 次请求 0 错误，所以瓶颈是同一 IP 的并发请求数。
客户端现在会：对 429/5xx/网络错误重试（200ms/800ms 退避）、把 HTTP 状态和
错误正文打出来、统计 `attempted/completed/中止`。

同时加了**全下 EV 调整**：Slumbot 终局响应带 `bot_hole_cards`，于是可以
重建整手牌，找到"河牌前双方全下"的时刻，用双方底牌 + 当时公共牌枚举剩余
发牌（转牌 44 种、翻牌 990 种精确；翻前 C(48,5) 太大 → 2048 次无放回抽样），
得到全下时的胜率，再用 `胜率 × 底池 − 投入` 作为这手的调整收益。这样剔掉了
最大的方差来源（runout），未调整的手仍用实际 `winnings`。`fold` 策略的
记账校验仍然成立（−67.5 筹码/手，理论 −75 加上 BB walk）。

600 手 `long_e0 + T0.1` 的实测：**−198.9 ± 142.3 筹码/手**（σ≈3478），
1000 手的标准误约 ±110（1.1BB/手）。**结论没变：不能声称领先 Slumbot。**

**22) 尖自对局（`--self-sharp-prob`）：同 seed A/B 一正一负，平均没有收益。**
让 10% 的对局里，对手座位用**当前权重**按部署温度 T=0.1 提取动作
（其余 10% 仍是普通自对局）。600 轮、其余配方完全相同：

| seed | 尖自对局 vs 同 seed 对照（12000 手） |
|---|---|
| 9001 | **+117.6 ± 39.4** |
| 9002 | **−187.8 ± 31.8** |

幅度和符号都随种子翻转，平均约 −35。原因大概是：尖对手的转移是用另一套
提取方式产生的，进入 PPO 后是 off-policy 样本（和快照对手同一口径），
10% 的配额不足以稳定学习，却能明显扰动 BB 网络（9002 的 BB −481）。
代码保留（默认关），**不作为训练配方**。

**23) 分座位选模型是选择偏差，不是新强度。** `match` 的两遍（被测方坐 SB /
坐 BB）是两批独立对局，固定对手时总分可以按座位相加。用同一个发牌 seed 999
测各检查点的分座位分数（对 v12）：

| 模型 | SB | BB |
|---|---|---|
| sharp10 | **+65.5 ± 35.7** | +118.8 ± 65.7 |
| sharp10_s2 | +51.1 ± 30.9 | −249.5 ± 109.8 |
| v9b | −236.4 ± 75.8 | **+169.8 ± 70.0** |
| v9d | −74.3 ± 56.9 | +103.6 ± 66.2 |
| long_e0 | −319.6 ± 83.0 | +77.8 ± 72.3 |

按"SB 取 sharp10、BB 取 v9b"拼出 `/tmp/hybrid1`，在 seed 999 上预期
(65.5+169.8)/2 ≈ +118。**但换一批发牌（seed 777）复测只有 +2.7 ± 27.2**
——winner's curse：在同一批发牌上取 max，必然把噪声当信号。
`--a-sb/--a-bb` 保留作工具，但**不要用同一批评估挑座位**。

**24) 同牌对调训练（`--duplicate-deals`）：没有收益。** 相邻两局用同一副牌、
交换底牌，把牌运成分在成对样本里抵消。600 轮同 seed（9001）对照：

| 配方 | vs 同 seed 对照（12000 手） |
|---|---|
| 同牌对调 | **−54.9 ± 39.6** |

牌运方差本来就被 critic 的完美信息 baseline 吸收了大半，剩下的相关性还可能
降低样本多样性。**不作为训练配方。**

**25) 多种子参数平均（soup）仍是唯一稳定的正向改动。** 用 long_e0 配方
（600 轮纯 PPO + wd=1e-3 + extra 0）跑 seed 9001/9002/9003，然后两两平均：

| 组合 | vs ckpt_v12（12000 手，T0.1 vs T0.1） |
|---|---|
| soup(9002, 9003) seed 999 | **+79.9 ± 25.3** |
| soup(9002, 9003) seed 5555 | **+29.0 ± 23.1** |
| soup(9002, 9003) seed 8888 | **+48.2 ± 24.9**（三个种子合并 **+52 ± 14**） |
| soup(9002, 9003) vs long_e0 | **+122.3 ± 28.3** |
| soup(9001, 9002, 9003) seed 999 | −5.7 ± 16.9 |

**两个独立种子平均稳定赢 v12 约 +0.5BB/手**（三个发牌种子同向，3.7σ），
但把 9001 也平均进去反而归零——同一配方下不同种子的"盆地"并不等价，
等权平均不总成立。**注意：更多种子不是更好**，见第 27 条。

**26) 更长训练（600 → 1800 轮）有明确增益，但还不足以单独超过 v12。**
同一个 seed（9001）直接续训到 1800 轮，前 600 轮与 long_e0 逐位相同，所以
这是纯"训练规模"对照（12000 手同发牌 H2H）：

| 对照 | 结果（T0.1 vs T0.1） |
|---|---|
| longe0_1800 vs long_e0（600 轮） | **+137.6 ± 34.2** |
| longe0_1800 vs ckpt_v12 | −12.4 ± 24.9 |
| longe0_1800 vs soup(9002,9003) | −90.1 ± 27.4 |

**多训 1200 轮换来 +1.38BB/手**，但 1800 轮的绝对水平仍只是 v12 级；
同为 ~10 分钟成本的 soup(600×2) 直接赢 v12 +54，比 1800 轮（−12）更划算。

继续训到 3600 轮（同 seed 再 +1800）：**3600 vs 1800 只有 +10.2 ± 37.6**，
**3600 vs v12 +6.4 ± 28.1**——规模曲线在 1800 轮附近已经触顶，
不再是"多训就涨"。要提升只能换配方或换结构。

**27) "更多种子平均"不成立；两两 soup 的收益也不均匀。** 用同一配方跑
seed 9001~9007，做多层平均（全部 12000 手，T0.1 vs T0.1，seed 999）：

| 组合 | vs ckpt_v12 |
|---|---|
| soup(9002, 9003) | **+79.9 ± 25.3**（另两个发牌种子 +29.0 / +48.2） |
| soup(9004, 9005) | −23.5 ± 20.5 |
| soup(9006, 9007) | +22.5 ± 27.4 |

**47) 新增 `policy-stats`：我们自己的动作分布，和 Slumbot 完全相反。**

| 节点 | T=1.0 | T=0.1 |
|---|---|---|
| SB 翻前开牌 | raise 82% / limp 13% / fold 5% | raise 100% |
| **BB 面对开牌** | fold 32% / **call 9.9%** / 3-bet 58% | fold 50.5% / **call 0.3%** / 3-bet 49% |
| SB 面对 3-bet | fold 38% / call 32% / 4-bet 30% | fold 52% / call 28% / raise 20% |
| **BB 翻牌先动** | **下注 81%**（0.61 底池）/ 过牌 19% | 下注 82% |
| **BB 翻牌面对注** | **fold 59%** / call 17% / raise 24% | fold 57.5% |

内部基准（规则/搜索机器人都会对加注弃牌）全面为正、对 Slumbot 却打平偏负。
**下一步的修复方向不是继续加激进，而是补上平跟/摊牌这一半。**

**69) 结构性改动 v1：不完全信息「范围胜率」信念头 + 信念残差评分支路。**
actor 里新增两套参数（旧的 14 个参数形状完全不变，旧检查点可无损加载）：

- **信念头**：`aux1: Linear(nodeDim,128) -> ReLU -> aux2: Linear(128,1) -> sigmoid`
  输出 `eqHat`，输入只有 node+序列（**不含对手底牌**），回归标签是开天眼
  真实胜率（`extra[104]`，每手已知双方底牌时的精确/抽样胜率）。
  它的条件期望就是"我的牌 vs 对手范围"的胜率——正是大池决策缺的量。
- **残差支路**：`auxAct1: Linear(17,64) -> ReLU -> auxAct2: Linear(64,1)`，
  输入 = 动作特征 16 维 + **detach 的 eqHat**，输出直接加到该动作的分数上。
  末层零初始化 => 旧模型/未训练时策略完全不变；detach 保证策略梯度不会
  污染信念头的校准（信念头只由回归损失塑形）。
- 训练：`--aux-equity-coef F`（默认 0）。日志新增
  `aux MSE/MAE 预测均值/标签均值`，可以直接看校准有没有在学。
- 兼容性：旧检查点严格加载失败后按 `lstm/l1..l4/head` 六个子归档逐个
  读取（`torch::NoGradGuard` + `copy_`），新参数保持初始化值；
  Adam 状态形状对不上时放弃恢复动量，模型权重不受影响。

**受控 A/B**：同一配方（从零 2400 轮：教师 400 + PPO 2000，seed 9101）
`--aux-equity-coef 0.3`，对照是同配方的 `/tmp/smallnet_d`。结果见下一条。
