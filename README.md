# PerfectTexasCPP

单挑无限注德州（Heads-Up No-Limit Hold'em）的**自对局强化学习**，C++17 + LibTorch，
训练循环全是 C++，没有 Python。

这一版把原来的 CFR / MCCFR 求解器整个删掉，换成和兄弟项目
[PerfectDouCPP](https://github.com/esrrhs/PerfectDouCPP) 同一套算法：
**不完全信息 Actor + 开天眼 Critic 的完美信息蒸馏 + PPO**。行为序列和底牌一起进特征，
不再查信息集表。

---

## 一、改了什么

| | 重构前 | 重构后 |
|---|---|---|
| 算法 | CFR / CFR+ / DCFR / external-sampling MCCFR | PPO + GAE + 完美信息蒸馏 |
| 策略表示 | 信息集哈希表（街 + 牌力桶 + 下注历史） | 神经网络，输入 = 底牌 + 公共牌 + 行为序列 |
| 动作抽象 | `ActionSpace` 预设，最多 7 个动作 | 8 个全局槽位（弃 / 跟 / 5 档尺寸 / 全下） |
| 对手 | 无（两人零和自对局恒为 0） | 分层联赛（最新 + 历史快照 + 规则机器人） |
| 评估锚点 | 可利用度（完全遍历）+ 存盘策略对打 | 规则机器人 + 随机 + 自对局 |
| 依赖 | 零依赖，header-only | LibTorch（Actor/Critic 用 `torch::nn`） |
| 代码量 | 4800 行（含 Kuhn / Leduc / BR） | 约 3400 行（规则 / 特征 / 采样 / PPO / 网络 / CLI） |

删掉：`cfr.hpp`、`mccfr.hpp`、`br.hpp`、`kuhn.hpp`、`leduc.hpp`、`equity.hpp`、
`holdem.hpp`（多路 + 边池的规则引擎，换成单挑专用的 `hu.hpp`）。
留下：`card.hpp`（52 张牌与 O(n) 牌力评估）、`strength.hpp`（169 类翻前胜率表、
翻后精确百分位、听牌出路）——牌力评估和牌力抽象这两块是旧版最硬的部分，没必要重写。

## 二、算法

### 两个网络，两套参数

单挑两个座位（小盲 SB / 大盲 BB）位置不对称，所以**每个座位一套 Actor + Critic**，
共 4 个网络。这和 PerfectDou 的"地主 / 下家 / 上家各一套"是同一个做法。

**Actor（不完全信息）** —— 只看得见自己该看见的东西：

```
LSTM(12 步 × 12 维行为序列) → h_last [128]
x     = concat(节点特征 388, h_last)            → 516
joint = concat(x[动作所属样本], 动作特征 16)     → 532
MLP: 532 → 256 → 256 → 256 → 512 → 1（ReLU，最后一层零初始化）
每个合法动作一个分数 → scatter 成 [B, 8] 的 logits，非法动作为 -1e9
```

`l1` 做了**分解投影**（节点部分只算一次，再按动作 gather），省掉把节点特征复制 L 遍的
开销——对应 PerfectDouCPP 的 `models.cpp`。

**Critic（开天眼）** —— 这是"开天眼、实时对齐"的另一半：

```
LSTM(同一条行为序列) → h_last
x = concat(节点特征 388, h_last, 开天眼特征 108)  → 624
MLP: 624 → 256 → 256 → 256 → 256 → 1
```

开天眼特征 108 维 = **对手两张底牌（2×52）+ 完美信息胜率 + 底池赔率 + 边际**。

它和 Actor 在**同一个进程、同一个更新循环**里同步训练：每轮先采样、再一起更新、
每 50 轮把权重快照进联赛池，没有异步延迟，也没有单独的推理服务。Actor 永远看不到
对手底牌，Critic 永远看得到——蒸馏就发生在 `A = R − V_开天眼(s)` 这一步：完美信息的
价值当基线，把"运气"从优势里扣掉，留下的才是动作的功劳。

### 特征

| 组 | 维度 | 内容 |
|---|---|---|
| 自己的底牌 | 104 | 2 × 52 one-hot |
| 公共牌 | 260 | 5 × 52 one-hot（未发出的全 0） |
| 标量 | 24 | 底池、跟注额、双方筹码、底池赔率、街、位置、SPR、加注次数、全下标志、**自己的牌力百分位**、听牌出路、翻前 169 类号 |
| 行为序列 | 12×12 | 最近 12 个动作：谁、哪条街、类型 one-hot、金额、动作后底池 |
| 开天眼 | 108 | 对手底牌 104 + 完美信息胜率 + 底池赔率 + 边际 |
| 动作 | 16 | 类型 one-hot + 金额/底池 + 金额/筹码 + 动作后底池与筹码 + 是否全下 + 是否加注 |

底牌用 52 维 one-hot 而不是 13×4 矩阵：花色关系让网络自己学，少一层手工结构。

### 动作

8 个全局槽位，和具体局面无关——所以一个 `kNumActions = 8` 的输出头覆盖所有决策点：

| 槽 | 含义 | 金额 |
|---|---|---|
| 0 | 弃牌 | — |
| 1 | 过牌 / 跟注 | 跟到当前最大投入 |
| 2–6 | 5 档尺寸 | 翻前：上次加注额的 2.2 / 2.5 / 3 / 4 / 5.5 倍；翻后：底池的 1/3 / 1/2 / 2/3 / 1 / 1.5 倍 |
| 7 | 全下 | 全部筹码 |

每街最多 3 次主动加注（开池 / 3-bet / 4-bet），加注额去重，小于最小加注的档位钳到最小
加注，超过筹码的并进全下。翻前用"上次加注额的倍数"而不是底池比例，是因为翻前底池只有 3、
底池比例算出来的尺寸全挤在 4~5，中间到 200 是空的（旧版 README 里踩过一次）。

### 奖励

```
r_terminal = 净筹码 / 起始筹码            (∈ [-1, 1])
r_shape    = coef × ΔΦ                    (开天眼稠密奖励)
Φ(s)       = (开天眼胜率 × 底池 − 自己已投入) / 起始筹码
```

Φ 的含义是"从此刻起双方都不再下注时的期望净收益"，所以它是一个真正的势函数：

- 弃牌不改变底池也不改变投入 → `ΔΦ = 0`，不会凭空奖励弃牌；
- 跟注 b：`ΔΦ = b·(2·eq − 1)`，胜率过半才有正收益；
- 归一化到起始筹码是为了让奖励落在 O(1)：直接用筹码（±200）会让价值网 MSE 上千，
  梯度全被它吃掉（实测过，见第五节）。

这一条**踩过一次坑**：最早的 Φ 写成 `底池 × (2·eq − 1)`，少了"自己已投入"这一项，
于是对手往底池里下注就把 Φ 推高——弃一手 60% 胜率的牌也能拿到正奖励。实测后果是
策略在 50 轮内塌成"从不弃牌"，摊牌率 44% → 80%。

### PPO / GAE

和 PerfectDouCPP 的 `ppo.cpp` / `ppo_learner.cpp` 一致：γ=1、λ=0.95、裁剪 0.2、批内
优势标准化、actor / critic 各一个 Adam（梯度裁剪 0.5 / 5.0，因为价值在筹码量级上）、
KL 早停（0.03）、掩码 softmax 带"全非法时退化成均匀分布"的兜底。

额外加了一条：**策略更新完之后 critic 再多跑 8 个 epoch**。理由见第五节——价值基线
不准时，PPO 会把"稳输一小注"的弃牌算成好棋。

### 联赛

每手牌给两个座位各自独立抽对手：

| 概率 | 对手 |
|---|---|
| 0.30 | 历史快照池（最近 8 个，滚动淘汰） |
| 0.05 | 规则机器人（牌力百分位 + 底池赔率） |
| 0.65 | 当前最新策略 |

历史快照是为了打断自对局的循环策略。规则机器人同时充当评估锚点——CFR 删掉之后，
"到底比谁强"需要一个固定标尺，它就是那个标尺。

`--rule-prob` 就是课程旋钮（默认 0.05）。拉到 0.5 会让 `vs 规则机器人` 一路涨到
+11.5，但代价是策略退化成"不看牌的固定下注模式"——见第五节，这个旋钮是会把指标刷上去
而不把牌打好的典型。

## 三、和 PerfectDouCPP 的对应关系

| | PerfectDouCPP（斗地主） | PerfectTexasCPP（单挑德州） |
|---|---|---|
| 座位 | 地主 / 下家 / 上家三套模型 | 小盲 / 大盲两套模型 |
| Actor 输入 | 12×15 牌矩阵 × 39 + 1676 维节点 + LSTM(10×540) | 388 维节点 + LSTM(12×12) |
| 动作表示 | 621 维抽象动作 + 186 维动作特征，scatter 到 2048 | 8 个槽位 + 16 维动作特征 |
| Critic 额外信息 | 另两家手牌 + 最小出牌步数（362 维） | 对手底牌 + 完美信息胜率（108 维） |
| 稠密奖励 | `Δ(n地主 − min(n农民))` × 0.2 | `Δ(胜率 × 底池 − 投入)` × coef |
| 结算 | ADP ±2·2^炸弹 | 净筹码 / 起始筹码 |
| 基线对手 | 外部 DouZero TCP | 内置规则机器人 |
| 吞吐（单线程 CPU） | ~8.8 s / 512 局 | **~1.4 s / 384 局** |

```
include/texas/

  ppo.hpp       GAE、掩码 softmax

  rollout.hpp   自对局采样、联赛、规则机器人
  learner.hpp   PPO 学习器
  eval.hpp      对固定基准的强度评估
src/
  hu.cpp features.cpp nn.cpp rollout.cpp learner.cpp eval.cpp main.cpp
tests/
  test_main.cpp 87 条断言
```

LibTorch 默认找 `~/libtorch`，也可以显式指定：

```bash
curl -L -o /tmp/libtorch.zip \
  https://download.pytorch.org/libtorch/cpu/libtorch-macos-arm64-2.5.1.zip
unzip -q /tmp/libtorch.zip -d ~

cmake -S . -B build -DCMAKE_PREFIX_PATH=$HOME/libtorch -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

`-G "MinGW Makefiles"` + `mingw32-make -C build -j`。

## 五、实测

### 自测

```
[牌与牌力评估]  快路径 vs 暴力枚举：5 万组随机牌 × (5/6/7 张) 全部一致
[规则引擎]      随机对局 2 万手：零和违例 0、必然终局、平均 3.97 个决策
[特征编码]      底牌恰好 2 个 1、公共牌 0 个、开天眼对手牌 2 个、动作 one-hot 互斥
[PPO 数学]      掩码 softmax 和为 1、非法槽位概率 0、全非法时退化成均匀
[网络前向]      logits 形状 [B,8]、未出现的槽位是 -1e9、存盘往返逐位相同
87 通过, 0 失败
```

### 基线

```
$ ./perfecttexas bench --hands 500
未训练策略 vs 规则机器人: -9.239 ± 4.186 筹码/手 (-462.0 bb/100)
```

未训练网络（head 零初始化 → 8 个动作等概率）每手输 9.2 个筹码，这就是训练要跨过的起点。
标准误很大（±4.19）：一次全下就是 ±200 的摆动，单副牌标准差约 132 筹码。
换成 8000 手更稳的同一个量是 **−8.08 ± 1.57**（见第五节表格），以下统一用这个。
同一起点在随机策略上是 −0.79 ± 1.23——均匀随机打均匀随机，零和对称，本来就该是 0。

### 管线体检：给它一个已知正确的优势，它学不学得会？

训练不动时，先分清"链路有 bug"还是"信号太吵"。`sanity` 把优势换成**动作相关、
且已知与牌力强相关**的合成信号（强牌加注给正优势、弱牌弃牌给正优势），跑 400 轮 PPO：

```
AA   fold=0.02 call=0.01 r4=0.14 r5=0.15 r6=0.15 r8=0.16 r11=0.18 jam=0.19
72o  fold=0.31 call=0.09 r4=0.10 r5=0.10 r6=0.10 r8=0.09 r11=0.09 jam=0.13
85o  fold=0.41 call=0.10 r4=0.07 r5=0.07 r6=0.07 r8=0.07 r11=0.07 jam=0.12
```

方向完全正确（AA 弃牌 2%、加注 62%；85o 弃牌 41%）。**说明 actor / PPO / 特征 /
动作映射这条链路是通的**，真实训练学得慢不是 bug。

顺带：这个测试的第一版把优势写成"只跟牌力有关、与动作无关"，结果弱牌反而学去全下。
原因很清楚——每个动作被同等放大时政策没有偏好可学，剩下的漂移全是噪声。测试本身
也得设计对。

### 价值网的容量

`critfit` 把一批 508 条自对局数据固定住，只训练 critic：

```
step  100  rmse 0.0651
step  200  rmse 0.0421
step  300  rmse 0.0016     ← 这 batch 的回报标准差本身是 0.5534
```

300 步就能拟合到几乎为零（是记忆，不是泛化）。所以价值网不缺容量，训练循环里缺的是
**步数**：每轮只有约 1000 条新样本，4 个策略 epoch + 8 个价值 epoch ≈ 36 个梯度步，
而目标分布每轮都在变。

### 开天眼稠密奖励的系数：三组对照

单种子、512 局/轮，跑到 100 轮时的 `eval vs rule`（正数 = 比规则机器人强）：

| 组 | coef | 100 轮时 | 后续 |
|---|---|---|---|
| A | 0.05 | +0.47 ± 1.57 | **塌缩**：弃牌率 91%、小盲收池率 1.8%、熵 1.41 → 0.32 |
| B | 0.30 | **+4.57 ± 1.83** | 稳定，弃牌率 23% |
| C | 关掉 | +2.48 ± 2.22 | 稳定，但熵掉到 0.94 |

三条结论都只有单种子证据，**按后面"自对局为什么不单调"一节的结论，这几行不能当定论**，
只有"0.05 会塌缩"这一条因为伴随熵从 1.41 掉到 0.32、有独立旁证，可以算数：

1. **开天眼稠密奖励有用**：0.30 那组在 100 轮就到 +4.57，是唯一明显压过规则机器人的。
2. **系数太小反而更危险**：0.05 那组塌缩了。稠密信号太弱时，弃牌的"确定性小损失"
   相对价值基线显得更划算，策略一路滑向全弃——自对局里最常见的塌缩形态。
3. **关掉也能到 +2.48**，但熵掉得最快（0.94），说明它正往"小盲猛加、大盲狂弃"的
   退化均衡走。

### 长跑的三个基准（核心结果）

从 −8 筹码/手起步，训练到 600 轮（约 23 万手）之后。每格都是 8000 手 × 两个座位
（合计 16000 手、同一次评估循环），不是训练日志里的抽样评估：

| 训练配置 | 轮数 | vs 规则机器人 | vs 随机策略 |
|---|---|---|---|
| 未训练（head 零初始化 → 8 个动作等概率） | 0 | −8.08 ± 1.57 | −0.79 ± 1.23 |
| 自对局为主 `--rule-prob 0.05 --league 0.30` | 400 | +2.65 ± 0.61 | +5.98 ± 0.74 |
| 同上续训 200 轮 | 600 | +5.39 ± 0.66 | +3.43 ± 0.82 |
| 机器人课程 `--rule-prob 0.50 --league 0.15` | 600 | **+11.52 ± 0.67** | **−0.04 ± 0.68** |

单位是筹码/手，`±` 是标准误；换算成 bb/100 就是 ×50。

只看第一列，课程组是自对局的两倍还多（+576 对 +269 bb/100）。第二列直接把它否了：
**打随机策略是 −0.04，和未训练一模一样。** 未训练的"≈0"是必然的——两边都是均匀随机，
零和对称。所以课程组的第二列说明它**一点通用牌力都没学到**，只学会了怎么打这个特定的
规则机器人。

**单一基准是可以刷的。** 只要"小盲几乎总是加注"，vs 规则机器人就能推到 +11.5，因为
机器人面对加注的应对完全可预测。这不是把牌打好了，是把指标打好了。后面任何"提升"都要
两个基准一起看。

### 自对局为什么不单调

seed 11 那次 400 轮长跑，8 次评估：

```
轮数     50     100     150     200     250     300     350     400
vs规则  -0.98  -0.37  +0.75  +1.48  -4.17  +3.61  +0.21  +2.15
```

±1.7 是标准误，−4.17 和 +3.61 之间隔了 4.5 个 σ——**是真的换了个策略，不是噪声**。

再跑三个种子各 150 轮（同超参、同代码），全部在 50→150 轮之间退化：

| 种子 | 50 轮 | 100 轮 | 150 轮 |
|---|---|---|---|
| 21 | −0.85 | −7.18 | −4.70 |
| 22 | +0.80 | −4.32 | −10.00 |
| 23 | −1.72 | −4.68 | −4.02 |

150 轮时跨了 11 个筹码/手。**150 轮以内的单种子结论没有意义**，包括上一节表格里
400 轮以下的行——那次 +2.65 也是四个种子里挑出来的一个。

自对局还会短暂塌缩：自对局组跑到第 300 轮时 `jam% 25.2`、熵 0.62（"见牌就全下"），
第 400 轮自己爬回来了。这种瞬时塌缩在日志里只占一行，很容易漏掉——所以看 `jam%` 和
`熵` 比看 loss 有用。

### 网络到底有没有在看牌

`probe` 打印同一批局面上各动作的平均概率。两个模型的翻前（小盲先行动）对比：

```
自对局 400 轮                                   机器人课程 600 轮
AA   fold=0.11 call=0.15 r4=0.17 r5=0.16 ...    AA   fold=0.01 call=0.02 r4=0.24 r5=0.24 ...
KK   fold=0.13 call=0.18 r4=0.19 r5=0.16 ...    KK   fold=0.01 call=0.02 r4=0.25 r5=0.25 ...
AKs  fold=0.10 call=0.14 r4=0.17 r5=0.17 ...    AKs  fold=0.02 call=0.03 r4=0.25 r5=0.25 ...
72o  fold=0.18 call=0.21 r4=0.19 r5=0.16 ...    72o  fold=0.03 call=0.04 r4=0.27 r5=0.24 ...
```

`str` 是节点里的牌力特征（翻前 169 类胜率），`eq` 是开天眼胜率。

- 自对局模型：AA 和 72o 的弃牌率是 0.11 对 0.18，有分化，但只有 7 个百分点；
- 课程模型：0.01 对 0.03，**几乎没有分化**，四行的动作分布几乎重合。

课程组那个 +11.5 就是靠一个和底牌无关的固定下注模式打出来的，和上一节"vs 随机 = 0"
是同一件事的两面。

`sanity` 证明过链路能学牌（合成优势下 AA 弃牌 2%、加注 62%，85o 弃牌 41%），
所以这里是**信号强度**问题，不是 bug：一手牌的回报标准差约 0.5（已归一化），
"选对动作"的贡献比"牌运"小一个量级，十万手摊下来动作的功劳被淹掉了。

### 吞吐

单线程 CPU、384 局/轮、hidden 256 / LSTM 128：

| | |
|---|---|
| 采样 + 训练 | ~0.7 轮/s（≈270 手/s） |
| 其中采样 | ~55%（含每决策一次开天眼胜率，按街缓存） |
| 其中 PPO | ~45%（12 个 epoch × 约 3 个 minibatch） |
| 内存 | < 200 MB |

`--threads 1` 比默认多线程快约 20%：batch 很小（128），LibTorch 线程池的同步开销
比省下来的算力更贵。

## 六、当前状态与已知问题

**能做到的**：规则引擎、特征、动作抽象、自对局采样、PPO、完美信息蒸馏、联赛、课程
（`--rule-prob`）、存盘 / 续训、四个诊断工具（`bench` / `sanity` / `critfit` / `probe`）
都跑通了，87 条断言全过。策略确实在学：从 −8.08 筹码/手一路到 +5.39（vs 规则）/
+3.43（vs 随机），600 轮约 23 万手。

**做不到的**：

1. **没学会看牌。** 这是最根本的一条。训练到 600 轮，AA 和 72o 的翻前弃牌率是
   0.01 对 0.03——策略基本是一个和底牌无关的固定下注模式。`sanity` 证明链路能学牌，
   所以不是 bug，是 23 万手的样本量不够：这里每手牌只产生约 4 条样本，
   DouZero / PerfectDou 的量级是上亿手。
2. **单一基准会被刷。** 把机器人曝光拉到 0.5，vs 规则机器人能到 +11.52（+576 bb/100），
   但 vs 随机策略是 −0.04，等于未训练。衡量"强不强"必须至少两个不同风格的基准。
3. **单种子不可信。** 同一套超参下，150 轮的结果在 −10.00 到 +0.80 之间跨 11 个筹码/手。
   现在文档里任何单次评估都只能当参考，不能当结论。
4. **会短暂塌缩。** 观测到一次 `jam% 25%` + 熵 0.62 又自己恢复；也观测过更严重的
   "从不弃牌"（摊牌率 44% → 80%，见第二节 Φ 的踩坑记录）。抑制手段是熵系数 0.02 +
   critic 额外 8 个 epoch + 联赛快照，都只是缓解。根治要让价值基线足够准。
5. **"实时对齐"只是同步更新，不是同分布。** 采样用的价值网与更新后的价值网差一轮，
   GAE 用的是旧值。这对 PPO 是标准做法，但和 PerfectDou 的异步 buffer 不一样，
   没有做重要性修正。
6. **开天眼胜率是抽样。** 转牌 / 河牌精确枚举（44 / 1 种），翻牌前与翻牌用 32 次抽样，
   标准差约 4~9 个百分点。进特征没问题，当势函数会带来奖励噪声。
7. **没有 CFR 基准了。** 删掉之后强度只能对着两个启发式基准量。
   "+5.39 筹码/手"不等于"接近均衡"，它只说明"比规则机器人强"。
8. **单线程采样。** 每个线程要一份独立的模型副本（`cloneActor`），暂时没做；
   当前吞吐瓶颈是采样里的前向和每决策一次的开天眼胜率。

**下一步优先级**（按性价比重排过）：

1. **多基准混合评估**，并且把"vs 随机"写进训练期的日志。第 2 条问题是被单一指标
   骗出来的，先修度量再修算法。
2. 多线程采样 + 线程私有模型副本（预期 4~6 倍吞吐），同样的墙钟时间换样本量——
   直接对着第 1 条病根。
3. 采样端只收集 (s, a, logp, R)，价值网用独立回放缓冲多跑几轮，解决第 5 条。
4. 动作抽象再压一档做对照（现在是 5 档尺寸；旧 CFR 版本的实验说明"档数"是主要杠杆）。

## 七、命令行

```bash
# 训练（默认 400 轮 × 512 局）
./build/perfecttexas train --updates 400 --games 512 --out ckpt

# 第五节里那两组长跑的确切命令
./build/perfecttexas train --updates 400 --games 384 --threads 1 --lr 1e-3 \
  --entropy 0.02 --oracle-coef 0.3 --league 0.3 --rule-prob 0.05 \
  --eval-every 50 --eval-games 1000 --seed 11 --out ckpt

./build/perfecttexas train --updates 200 --games 384 --threads 1 --lr 1e-3 \
  --entropy 0.02 --oracle-coef 0.3 --league 0.15 --rule-prob 0.5 \
  --eval-every 50 --eval-games 2000 --seed 31 --out ckpt_curr
./build/perfecttexas train --resume ckpt_curr --updates 400 --games 384 --threads 1 \
  --lr 1e-3 --entropy 0.02 --oracle-coef 0.3 --league 0.15 --rule-prob 0.5 \
  --eval-every 100 --eval-games 2000 --seed 32 --out ckpt_curr

# 续训
./build/perfecttexas train --resume ckpt --updates 200

# 关掉开天眼稠密奖励，做对照
./build/perfecttexas train --no-oracle --out ckpt_no_oracle

# 评估：对规则机器人 / 随机 / 自对局（报结论至少 8000 手，两个基准都要跑）
./build/perfecttexas eval --resume ckpt --vs rule   --hands 8000
./build/perfecttexas eval --resume ckpt --vs random --hands 8000
./build/perfecttexas eval --resume ckpt --vs self   --hands 4000

# 诊断
./build/perfecttexas bench                # 未训练策略 vs 规则机器人
./build/perfecttexas sanity --steps 400   # 合成优势，验证 actor / PPO 链路
./build/perfecttexas critfit --steps 300  # 验证价值网容量
./build/perfecttexas probe  --resume ckpt # 打印具体局面的平均策略
```

训练日志（每轮一行）：

```
update   games  sbWin%    sd%   jam%  fold%   pgLoss    vLoss  entropy     kl   upd/s | batch
    40     384    47.7   50.8    8.5   13.8  -0.0262   0.0412   1.513 3.8e-02    0.70 | ret -0.049±0.733 val -0.063
```

`sbWin%` 小盲收池率、`sd%` 摊牌率、`jam%` 全下频率、`fold%` 弃牌频率——**这四个数
比 loss 更能看出策略是不是在退化**：`fold%` 冲到 80% 以上就是塌缩，`jam%` 长期高于
20% 说明还在乱推。`ret` 是回报均值 ± 标准差（单位是起始筹码的倍数），`val` 是价值网
的预测均值，两者差距过大说明 critic 没跟上。
