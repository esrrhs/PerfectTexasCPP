# 规则文档

这份文档只讲**规则本身**：牌局怎么走、什么动作合法、怎么结算，以及对着 ACPC
（Annual Computer Poker Competition）逐条对账的结果。算法、网络、训练配置见 `README.md`。

口径：**单挑无限注德州（Heads-Up No-Limit Hold'em, HUNL）的 Doyle's Game**，
即每一手牌开始前双方筹码都重置。规则对齐 ACPC 的
`holdem.nolimit.2p.reverse_blinds.game`。

实现位置：`include/texas/hu.hpp`、`src/hu.cpp`（纯 POD 状态 + 规则函数）。

---

## 一、常量

| 常量 | 值 | 说明 |
|---|---|---|
| `kStartingStack` | 20000 | 起始筹码 |
| `kSmallBlind` | 50 | 小盲 |
| `kBigBlind` | 100 | 大盲（= 100 筹码，所以"筹码/手"数值直接等于 bb/100） |
| 深度 | 200BB | 20000 / 100 |
| `kMaxSizes` | 16 | 每街的"下注尺寸带"数 |
| `kNumActions` | 19 | 弃 / 跟 / 16 带 / 全下 |
| `kMaxHist` | 64 | 一手牌的动作条数上限 |
| `kNoRaiseCap` | 0 | 每街加注次数上限，0 = 无上限 |

单位换算：`1 bb/100 = 10 mbb/g`。**永远弃牌的基线是 −750 mbb/g**（大盲丢 1000
毫大盲、小盲丢 500，平均 −750），这条已写成测试不变式。

## 二、牌局流程

**座位约定**（单挑固定，纯记账口径）：

| 座位 | 身份 | 翻前 | 翻后 |
|---|---|---|---|
| 0 | 小盲 SB = 按钮 | 先行动 | 后行动 |
| 1 | 大盲 BB | 后行动 | 先行动 |

> ACPC 的 2 人桌用"反向盲注"（按钮下小盲），和这里**完全同构**，只是玩家编号不同
> （ACPC 的 `firstPlayer = 2 1 1 1`，即他们的 2 号 = 我们的座位 0）。游戏树一致，
> 所以策略不需要区分。

**发牌**：开局一次发定 2 + 2 张底牌和 5 张公共牌，之后按街推进 `boardN`
（0 → 3 → 4 → 5），机会节点不再抽牌。

**四条街**：翻前 / 翻牌 / 转牌 / 河牌。本街结束条件：双方都行动过 **且** 本街投入相等；
有人全下则一次性发完 5 张直接摊牌。

**终局**：有人弃牌、河牌行动结束、或双方全下。

## 三、合法动作

### 3.1 四种动作

| 动作 | 何时合法 | 金额 |
|---|---|---|
| 弃牌 fold | 只有"需要加钱才能跟"时（`need > 0`） | 净损失本手已投入 |
| 过牌 / 跟注 check / call | 恒合法 | 跟到当前最大投入 |
| 加注 raise | 见 3.2 | `[minRaiseTo, maxRaiseTo]` 内**任意整数** |
| 全下 all-in | 恒合法（只要有筹码） | `contrib + stack` |

"弃牌只在需要加钱才能跟时合法"这条直接来自 ACPC：可以免费过牌时不允许弃牌。

### 3.2 加注区间

```
maxRaiseTo = contrib[我] + stack[我]                      // 全下金额
minRaiseTo = lastRaiseTo + max(lastRaiseSize, kBigBlind)  // 最小加注
             再钳到 [., maxRaiseTo]                        // 凑不出完整加注就只能全下
```

* `lastRaiseTo`：当前跟注所需的投入额；`lastRaiseSize`：上一次加注的增量。
* 本街无人下注时 `lastRaiseTo = 0`，于是**最小下注 = 1 个大盲**。
* 翻前开局 `lastRaiseTo = 100`（大盲），所以最小加注到 **200（2BB）**。
* `minRaiseTo > maxRaiseTo` 会被钳成相等，此时唯一的加注就是全下——
  这就是 ACPC 的"短全下"：把对手全下的加注只要 raise-by ≥ 1 就合法，
  不受最小加注约束。
* **对手已全下时不能再加注**（本街不再重新开火）。

### 3.3 加注次数与金额

* **每街加注次数无上限**（ACPC 口径）。最小加注至少 +1BB，所以最长序列是
  `200 → 300 → 400 → … → 6100`，**实测能连加 60 次**才被迫全下。
  旧版 `kMaxRaises = 3` 在第 4 次就把牌局砍成只剩弃 / 跟 / 全下；
  现在用 `--max-raises N` 可以把上限加回来做对照。
* **金额是任意整数**（和 ACPC 一样）。单个决策点上合法整数金额的**覆盖率实测 100%**：

  ```
  翻前 SB 首次行动        合法区间 [200, 19999]，11 个带，覆盖 19800 / 19800
  翻牌 池 200 筹码 19900  合法区间 [100, 19899]， 9 个带，覆盖 19800 / 19800
  翻牌 池 10000 筹码 15000 合法区间 [100, 14999]， 8 个带，覆盖 14900 / 14900
  ```

## 四、尺寸带（策略侧的抽象）

规则层是任意整数，但神经网络的输出必须有限维，所以策略侧拆成两层：
**槽表示"打多大这个量级"，金额在槽对应的连续整数区间里落点**。

* 19 个槽：弃 / 跟 / **16 个尺寸带** / 全下（`kSlotAllIn = kNumActions - 1`）。
* 带的分界点用扑克锚点，而不是等距切分：

  | 街 | 锚点 |
  |---|---|
  | 翻前 | 上次加注额的 2.2 / 2.5 / 3 / 4 / 5.5 / 8 / 12 / 20 / 35 / 60 倍 |
  | 翻后 | 跟注额之上加底池的 1/4 / 1/3 / 1/2 / 2/3 / 3/4 / 1 / 1.25 / 1.5 / 2 / 3 / 5 倍 |

  相邻锚点之间就是一个带 `[锚点_i, 锚点_{i+1} - 1]`，最后一个锚点到全下之前还有一段
  **尾带**。所以常用尺寸附近带很窄（精度高），离谱的超池只占一个宽尾带（不浪费槽位）。
* 落点：策略采样槽，金额在带内**对数均匀**取一个整数（`amountInBand(lo, hi, u)`）。
* 为什么 PPO 不用改：均匀分布的密度只跟带宽有关、不含参数，在重要性比值里
  **精确抵消**，`logp` 仍然只记槽的概率。

一个真实决策点的映射（翻前小盲首次行动，200BB）：

```
弃 / 跟 / [200-219] / [220-249] / [250-299] / [300-399] / [400-549] / [550-799]
/ [800-1199] / [1200-1999] / [2000-3499] / [3500-5999] / [6000-19999] / 全下 20000
```

## 五、结算

* 单挑等额投入，**只有一个底池，无边池**（ACPC 对多人的"每档投入一个池"在单挑退化为单池）。
* 有人弃牌：另一人收下整个底池，不亮牌。
* 摊牌：比牌（`showdownWinner` 返回 0 / 1 / 2，2 = 平分）。
* 平分：按 ACPC 的 "split evenly"。spec 没规定奇数筹码给谁，**本引擎给座位 0**
  （1 个筹码 = 0.005BB，策略上可忽略）。
* `payoff(s, p)` 返回净收益（筹码），恒满足零和：`payoff(0) + payoff(1) == 0`
  （2 万手随机对局零和违例 0，已写成测试不变式）。

## 六、和 ACPC 的逐条对账

对着 [ACPC protocol v2.0.0](http://www.computerpokercompetition.org/downloads/documents/protocols/protocol.pdf)
以及 `holdem.nolimit.2p.reverse_blinds.game` 的游戏定义：

| 项 | ACPC | 本引擎 | |
|---|---|---|---|
| 起始筹码 | `stack = 20000 20000` | 20000 | ✅ |
| 盲注 | `blind = 100 50` | 100 / 50 | ✅ |
| 每手重置 | Doyle's Game | 每手重置 | ✅ |
| 轮次与牌 | 4 轮、2 底牌、公共牌 0/3/1/1 | 同 | ✅ |
| 行牌顺序 | `firstPlayer = 2 1 1 1` | 座位 0 = 小盲 = 按钮，翻前先动、翻后后动 | ✅（仅编号不同） |
| 弃牌合法性 | 只有"需要加钱才能跟"时才能弃 | `need > 0` | ✅ |
| 加注合法性 | raise-by ≥ 1；要么全下，要么 raise-by ≥ max(上次 raise-by, 大盲) | `lastRaiseTo + max(lastRaiseSize, BB)`，钳到全下 | ✅ |
| 短全下 | 把对手全下的加注不受最小加注限制 | 全下槽恒合法 | ✅ |
| 加注次数 | 无上限 | 无上限 | ✅ |
| 下注金额 | 任意整数 | 任意整数，覆盖率 100% | ✅ |
| 对手全下后 | 不能重新开火 | `isRaisePossible` 检 `allin[对手]` | ✅ |
| 结算 | 单底池、平分 | 同 | ✅ |
| 平分奇数筹码 | spec 未规定 | 给座位 0 | ⚠️ 0.005BB |
| 单位 | mbb/g，永远弃牌 −750 | 同 | ✅ |

**还剩三处没对齐，而且都不在规则层**：

1. **动作空间是抽象的**：策略一次只在 16 个带里选，ACPC 的完整游戏是 19800 个动作。
   参赛队也都抽象，但抽象会带来可利用度下界——准确说法是"规则对齐了"，
   不是"在打 ACPC 的完整游戏"。
2. **评估没做同牌对调（duplicate match）**：ACPC 每手牌用同一副牌、两人换座位各打一遍，
   把发牌运气消掉；本引擎两遍独立发牌，所以同样手数的标准误更大。
3. **没有可利用度基准**：没有 CFR / 最佳响应求解器，现有数字不能换算成 ACPC 榜单强度；
   能对上的只有"永远弃牌 −750 mbb/g"这条下界标尺。

## 七、边界情况速查

| 局面 | 结果 |
|---|---|
| 翻前小盲首次行动 | 最小加注到 200（2BB），全下 20000 |
| 翻后无人下注、池 200 | 最小下注 100（1BB） |
| 小盲加到 1234 | 大盲的最小加注 = 1234 + (1234 − 100) = 2368 |
| 小盲加到 15000 | 大盲凑不出完整加注 → `minRaiseTo == maxRaiseTo == 19900`，只能全下 |
| 一直取最小档加注 | 200, 300, 400, …, 6100，共 **60 次** |
| 池 20000、身后 10000 | 只能打 100~4999 / 5000~6666 / 6667~9999，或全下 10000 |
| 池小于 1BB 的下注 | 被钳到最小下注 1BB |
| 对手全下 | 只剩弃 / 跟，不能加注 |

## 八、命令行与不变式

```bash
# 退回"每街 N 次加注"做对照（深度和金额仍是当前口径）
./perfecttexas train --max-raises 3
```

规则相关的不变式都在 `tests/test_main.cpp`，`./perfecttexas_tests` 一次跑完：

* `[规则引擎]` 2 万手随机对局：必然终局、零和违例 0。
* `[对齐 ACPC]` 200BB、大盲 = 2×小盲、默认无加注上限（能逼出 >3 次加注）、
  永远弃牌 = −750 mbb/g。
* `[任意下注金额]`
  * 任意合法整数可加注：`canRaiseTo(1234)`、`canRaiseTo(19999)` 为真，
    `canRaiseTo(199)`、`canRaiseTo(20001)` 为假；
  * 加注到任意金额后，下一次最小加注跟着重算；
  * 尺寸带首尾相接铺满 `[minRaiseTo, maxRaiseTo - 1]`，不重不漏、槽位唯一；
  * 单个决策点的可达金额 **> 1000 个**（旧版只有 5 个），且包含随手指定的 1234；
  * 带内落点单调、端点可达；
  * 短全下合法（`minRaiseTo == maxRaiseTo` 时全下仍可打）；
  * 规则机器人给出的金额始终合法，且随底池连续变化。
