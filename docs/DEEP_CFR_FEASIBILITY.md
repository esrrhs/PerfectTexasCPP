## 0. 结论摘要（待 §4 外部核实后定稿）

1. **「必须租云 GPU 做 Deep CFR」这个前提可能被高估了。** 项目内部文档与文献都指向：
   追上 Slumbot（到 −0.13 量级）有**三条**路，其中两条算力门槛远低于「大规模云 Deep CFR」：
   - **路线 A（AlphaHoldem 式纯 RL）**：文献口径 1 GPU + 64 核 × 3 天击败 Slumbot/DeepStack，
     与本项目配方最接近（分座位网络 + 历史联赛），最符合用户 RL 偏好。【§4 核实中】
   - **路线 C（robopoker 式表格 CFR + 翻后重解）**：内部笔记已核实开源 robopoker 打到
     −13.1 bb/100（=−0.131 BB/手），训练 ~1.94×10¹⁰ 遍历 ≈ **本地 16 核 1.5 天，无需云 GPU**。
   - **路线 B（Deep CFR / ReBeL）**：上限最高但遍历吞吐是硬约束，需云 GPU。【§4 核实中】
2. **本地瓶颈是 NN 前向/反向，不是环境/胜率**：训练 13.56 ms CPU/手，PPO 占 81.3%、
   rollout 99% 是网络前向（`OFFLINE_COMPUTE_REQUIREMENTS.md`）。真 NVIDIA GPU 能加速这 81%；
   本机 MPS 因小网算子启动开销端到端反而慢（README 第一节），所以「本机 GPU 无意义」只对 MPS 成立，
   对云端真 GPU 不成立。
3. **表格 CFR 的「关闭」是实现层面误杀，不是路线证伪**（`ROBOPOKER_CFR_NOTES.md` §5）：
   我们的 key 信息量不足 + 访问密度只有 robopoker 的 1/2900（43 vs 120,000 次/infoset）；
   ε≤2 门用错了对象（ε 是最坏-case 保证，不是「赢固定对手」）。重启需按 robopoker 验证过的
   key/抽象/抽取配方改，再决定要不要付遍历的钱。

## 2. 路线 C：robopoker 式表格 CFR + 翻后重解（内部已核实，本地可行）

证据全部来自 `docs/ROBOPOKER_CFR_NOTES.md`（对开源 robopoker 源码的读码笔记）：

- **强度**：robopoker `world+dirac`（蓝图+重解）对 Slumbot **−13.1 ± 14.0 bb/100**（86K 手）；
  纯蓝图 `dirac` −28.4 ± 6.0 bb/100（480K 手）。换算 −0.131 / −0.284 BB/手。
- **算力**：旗舰表 156K infoset、1.94×10¹⁰ 棵树遍历；按计划书实测 10 核 ≈ 8.6×10⁹ 迭代/天
  → **~2.3 天/10 核、~1.5 天/16 核**。训练资源 16 vCPU/120GB。**M1 Pro 付得起，前提是表压到 10⁵**。
- **机制**：蓝图提供「足够好的先验 + 剥削基线」，翻后每决策 **5 秒重解**补回 key 丢掉的底池/范围信息，
  按访问数与蓝图混合（不是直接拿噪声解去打）。
- **与我们失败的关键差异**：
  - 访问密度：我们 43 次/infoset vs 它 120,000 次（**2900×**）；CFR 收敛 O(1/√T)，43 次本不该收敛。
  - key 信息量：R2 证明瘦 key（去 potBucket/跨街历史）即使密度提到 746–1492 仍 ε 翻倍 → 瓶颈在 key。
  - 重解 prior：我们的部署期 turn/river CFR 用**自身策略**当范围先验（自指），外部为负；
    robopoker 用**训练好的蓝图**当先验。这是「重解能不能用」的分水岭。
- **caveat（不要过度解读）**：robopoker −0.131 与我们 stn2 的 CI 重叠（误差 > 差值）；
  它的优势是**样本量 + 管线完整度**（抽象→训练→重解→argmax 一条龙），不是「小表比大表强」。
  它的可利用度**未公开**（日志里的 "exploitability" 其实是 sum regret；NLHE 没接精确 BR）。

**重启路线 C 的工程量**（非算力）：① 按 potential-aware abstraction 重设 key；② 把访问密度提到 10⁵/infoset
（表压到 10⁵、遍历提到 10¹⁰）；③ 实现「蓝图先验 + 翻后重解 + 访问数混合」的完整管线。
项目已有 `blueprint-train`/`blueprint-br`/`rivercfr`/`turncfr` 砖块，缺的是 key 配方与重解集成。

## 3. 路线 B：Deep CFR / ReBeL（云 GPU，上限最高）

- 计划书 §9.5 / README §7：Deep CFR / ReBeL 需云端 GPU；本机 MPS 端到端更慢，继续 M1 Pro 无意义。
- 计算形态：遍历采样（CPU）+ 优势/遗憾网络训练（GPU）。GPU 只加速网络训练那一半；
  **遍历吞吐是硬约束**（当前 ~25k 决策/秒，Deep CFR 需 10⁶⁻⁷/秒，差两个量级）。
- ReBeL（NeurIPS 2020，FAIR）：RL + 公开信念状态搜索，两人零和可证收敛纳什，摘要称 HUNL 超人。
  代码 github.com/facebookresearch/rebel。【§4 核实算力口径与可复现性】
- 风险：遍历向量化/并行工程量大（≥2–3 周），大概率卡在遍历吞吐；蒸馏再遇「对手模型不匹配」。

## 5. 本地计算事实（成本模型基础，已实测）

来自 `docs/OFFLINE_COMPUTE_REQUIREMENTS.md`（M1 Pro，2026-11-09）：

- 训练 **13.56 ms CPU/手**（rollout 18.7% + PPO 81.3%）；wall 4.39 ms/手（2 workers）。
- rollout 99% 是 actor/critic 前向；PPO 100% 权重依赖 → 这两块（≈99.8% CPU）可被真 GPU 加速。
- 本地 `match` 批量吞吐 0.29 ms/手 wall；单局 B=1 部署 0.41 ms/决策（网络往返主导，计算仅 0.14%）。
- 推算 AlphaHoldem 规模（~1 亿局）在 M1 Pro：按 4.39 ms wall/手 ≈ **5 天**；真 GPU 加速 PPO 后更短。
