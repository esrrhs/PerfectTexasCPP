# 迭代账本（ITERATION LEDGER）

> 长期自治迭代的唯一记账处。每轮**只改一个变量**，走完闭环再进下一轮。
> 只记事实：假设、改动、快速环数字、外部数字、结论、可复现命令。失败直接写失败。

## 0. 目标与判据

- **主指标**：对 Slumbot 外部评测的 BB/手（全下 EV 调整）。
- **当前基线**：`stn2 + T=0.5`，**−0.808 ± 0.229 BB/手（6,088 手，95% CI ±0.449）**。
- **采纳门**：外部 12k 手、点估计 **≥ 基线 + 2σ**（按差值口径约 **+0.60 BB/手**）。
- **最终目标**：基线推到 **0 以上并稳定**；过门只是中途站。
- **诊断指标**（不改判据，只用来定位）：大池（>40BB）EV、SB/BB 分位、河牌弃牌错误成本、动作分布。
- **分辨率上限**：12k 手的候选 SE ≈ 0.17–0.19，2σ ≈ 0.34–0.40；叠加基线 SE 后约 0.60。
  小于这个量级的改进 12k 裁决不了，只能记“不可分辨”，要 36k 以上。

## 1. 每轮闭环

1. **假设**：为什么改这个杠杆、预期哪个指标动、动多少。
2. **快速环**：22 秒烟雾环 + 本地面板（rule/random/solid/mix 等锚点）；崩坏直接否决，不占外部机时。
3. **外部预筛**：过快速环后先打 1500–3000 手，只有明确超过 0.5 BB/手量级才上 12k 终审。
4. **记账**：无论接受/拒绝，都写在本文件。
5. **合并/回滚**：接受 → 更新基线数字与 README；拒绝 → 回滚代码，记录原因。
6. **换杠杆**：同一杠杆连续 3 轮无改善，换到特征表达 / 奖励设计 / 对手池 / 搜索与重解 / 数据规模。

**硬约束**：外部通道同时只跑一条；训练/实验用 `nice` 或限核；每轮留 seed、commit、命令行；
不许改评测口径、挑样本、按对手过拟合温度。

### R2 — 2026-11-08 — 瘦 key 对照（已完结，**拒绝**）

- **假设**：如果 ε 主要受“每 infoset 访问密度”支配，那么把底池桶与跨街历史移出 key 后，
  同样迭代数下 ε 应明显低于 `b256_r0`（260K 角、30M 时 ε=25.70）。
- **改动**：`packInfoset` 新增 `--key-slim`（slim=1 时 `potBucket(32)` 与 `hist(8bit)` 置零，
  key 只剩 `street + 牌桶 + 当前街序列 + 1 bit 座位`）；`meta.txt` 持久化 `slim`，
  train/br/distill/eval 自动跟随，混用拒跑。
- **快速环**：500K 冒烟 → 39,615 角、30k iter/s、无崩坏。
- **BR 结果**（1000 抽样、seed 424242、同抽象内抽样 BR）：

| 表 | 迭代 | 角数 | 访问/角 | ε（BB/手） |
|---|---:|---:|---:|---:|
| **slim B=256** | 30M | 40,194 | 746 | **47.818 ± 1.180** |
| **slim B=256** | 60M | 40,209 | 1,492 | **45.408 ± 1.091** |
| 对照 b256_r0 | 30M | 260,560 | 115 | 25.702 |
| 对照 b256_r1 | 60M | 1,387,344 | 43 | 22.691 |

- **结论**：**拒绝**。瘦 key 没有降低 ε，反而约为对照的 1.8–1.9 倍；60M 相对 30M 只降 5%
  （与 M0 的慢斜率一致）。**访问密度不是约束，key 里的信息量才是**——底池桶与跨街历史

- **后果**：按预设裁决，**表格 CFR 路线关闭**（不是“暂停待裁”）；不再做 R3（argmax/重解混合），
  表格 CFR 不再占用迭代预算。

#### R4 附：翻后重解缺失——一页纸关闭

- **需求**：robopoker 靠 5 秒级重解补“对手范围”这条信息；要补就得在部署时每决策重解。
- **本机实测**：转牌 CFR 子博弈 **4.2 秒/手**（≈100× 成本），且外部/内部双负
  （solid −219.9 ± 69.0，3.2σ；pro −223.5 ± 80.1，2.8σ）。毫秒级做不到，秒级做过两次都输。
- **河牌单独做**：min-pot 4000（接管 2.7%）≈ 0（−0.01 ± 0.35，1,500 手）；
  min-pot 1500（接管 12.0%）**−0.69 ± 0.29**（4,500 手，比 0 低 2.4σ）。接管面越大越亏。
- **机制**：重解的对手范围只能用我们自己的策略当先验，而大池恰好是先验最不准的地方；
  越依赖重解，越把“自己打自己”的偏差放大（README 第三节“共同机制”）。
- **结论**：**关闭，不再开任何部署期求解算子**。除非先有与 Slumbot 行为拟合的范围模型，
  而那条已证伪（行为克隆平衡 acc ≈ 0.30，raise 预测 10.6% vs 真实 16.4%）。

### R5 — 2026-11-08 — 大池优势加权（训练臂，**拒绝**）

- **假设**：大池决策只占样本的百分之几，却承担几乎全部 EV 方差；PPO 的批内优势标准化
  不会按底池重新分配梯度份额。按决策时底池给策略梯度加权，应把优化容量推到大池，
  快速环的大池 EV 应改善，锚点不应崩。
- **改动**（唯一变量 = 策略梯度权重；联赛配比/超参与 `abl_ctrl` 完全相同）：
  `--pot-adv-weight 1.0`，权重 `w = clamp(底池/1500, 1, 3)^1`（1500→1.0，3000→2.0，≥4500→3.0），
  只乘在 PPO 优势上，critic 的回报不改。代码位置：`Transition::potWeight`（`rollout.hpp`）、
  写入点在 `rollout.cpp` 记录 `gameId` 之后、加权点在 `learner.cpp::buildBatch` 的标准化之后。
- **快速环**（16k H2H vs `stn2`，seed 424242，与 `abl_ctrl` 同口径）：

| 臂 | H2H 筹码/手 | >4000 底池 | solid | rule |
|---|---:|---:|---:|---:|
| `abl_ctrl`（对照，无加权） | **+13.0 ± 20.5** | 1762 手 **+227.5** | +503.3 | +1933.7 |
| `r4_potw`（加权） | **−62.0 ± 19.0** | 2349 手 **−327.2** | +490.2 | +1838.0 |

  动作分布显示**机制性塌缩**：BB 面对开牌从 `fold 74.5% / raise 14.5%` 变成
  `fold 16.3% / raise 72.4%`（翻前变成 3-bet 机器），BB 河牌面对下注 `fold 100%`（n=20）。
  训练末锚点也同步下滑（rule +1748 vs 对照 +2194，self −306 vs −144）。
- **外部**：未打（快速环已崩，按纪律不占外部机时）。
- **结论**：**拒绝**。按底池加权把“别在大池犯错”学成了“大池少投入”的保守塌缩，
  与目标方向相反；说明大池的瓶颈不是梯度份额，而是**没有对手范围信息可用**
  （与 R4 的结论一致）。该开关保留在代码里但默认 0，并列入 README 关闭项。
