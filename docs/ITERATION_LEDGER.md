# 迭代账本（ITERATION LEDGER）

> 长期自治迭代的唯一记账处。每轮**只改一个变量**，走完闭环再进下一轮。
> 只记事实：假设、改动、快速环数字、外部数字、结论、可复现命令。失败直接写失败。

## 0. 目标与判据

- **主指标**：对 Slumbot 外部评测的 BB/手（全下 EV 调整）。
- **当前基线**：`stn2 + T=0.5`，**−0.681 ± 0.163 BB/手（12,088 手，95% CI ±0.320）**。
  2026-11-09 凌晨把 s96006–s96009 四段（各 1500 手，全下调整 −0.715 / −0.921 / −0.577 / +0.008）
  并入后重算；旧读数 −0.808 ± 0.229 / 6,088 手。
- **采纳门**：外部 12k 手、点估计 **≥ 基线 + 2σ**。按差值口径（12k vs 12k）SE=0.231，
  **2σ ≈ 0.46 BB/手 → 阈值 −0.22**。
- **最终目标**：基线推到 **0 以上并稳定**；过门只是中途站。
- **诊断指标**（不改判据，只用来定位）：大池（>40BB）EV、SB/BB 分位、河牌弃牌错误成本、动作分布。
- **分辨率**：12k 候选 2σ ≈ 0.46；3,000 手 ≈ 0.74；**1,500 手 ≈ 0.99（只够做崩溃筛查）**；
  要把 2σ 压到 0.25 需两臂各 ~36k 手。

## 1. 每轮闭环

1. **假设**：为什么改这个杠杆、预期哪个指标动、动多少。
2. **快速环**：22 秒烟雾环 + 本地面板（rule/random/solid/mix 等锚点）；崩坏直接否决，不占外部机时。
3. **外部预筛**：过快速环后先打 1500–3000 手，只有明确超过 0.5 BB/手量级才上 12k 终审。
4. **记账**：无论接受/拒绝，都写在本文件。
5. **合并/回滚**：接受 → 更新基线数字与 README；拒绝 → 回滚代码，记录原因。
6. **换杠杆**：同一杠杆连续 3 轮无改善，换到特征表达 / 奖励设计 / 对手池 / 搜索与重解 / 数据规模。

**硬约束**：外部通道同时只跑一条；训练/实验用 `nice` 或限核；每轮留 seed、commit、命令行；
不许改评测口径、挑样本、按对手过拟合温度。

### R2 — 2026-11-08 — 瘦 key 对照（已完结，**拒绝**）

- **假设**：如果 ε 主要受“每 infoset 访问密度”支配，那么把底池桶与跨街历史移出 key 后，
  同样迭代数下 ε 应明显低于 `b256_r0`（260K 角、30M 时 ε=25.70）。

- **BR 结果**（1000 抽样、seed 424242、同抽象内抽样 BR）：

| 表 | 迭代 | 角数 | 访问/角 | ε（BB/手） |
|---|---:|---:|---:|---:|

#### R4 附：翻后重解缺失——一页纸关闭

- **需求**：robopoker 靠 5 秒级重解补“对手范围”这条信息；要补就得在部署时每决策重解。
- **本机实测**：转牌 CFR 子博弈 **4.2 秒/手**（≈100× 成本），且外部/内部双负
  （solid −219.9 ± 69.0，3.2σ；pro −223.5 ± 80.1，2.8σ）。毫秒级做不到，秒级做过两次都输。
- **河牌单独做**：min-pot 4000（接管 2.7%）≈ 0（−0.01 ± 0.35，1,500 手）；
  min-pot 1500（接管 12.0%）**−0.69 ± 0.29**（4,500 手，比 0 低 2.4σ）。接管面越大越亏。
- **机制**：重解的对手范围只能用我们自己的策略当先验，而大池恰好是先验最不准的地方；
  越依赖重解，越把“自己打自己”的偏差放大（README 第三节“共同机制”）。
- **结论**：**关闭，不再开任何部署期求解算子**。除非先有与 Slumbot 行为拟合的范围模型，
  而那条已证伪（行为克隆平衡 acc ≈ 0.30，raise 预测 10.6% vs 真实 16.4%）。

### 附：训练侧“胜率”语义核实与实测（R9 前置，2026-11-09）

外部假设是“texas_algorithm 已有不同公牌下的绝对精确胜率，可直接替换训练侧采样”。
核实结果：**那张表是另一个量，不能替换**。逐条：

1. **`phiOf` 用的胜率 = 2+2+N（双方真实底牌）**，不是“对随机对手范围”。
   `src/hu.cpp:353-412` 的 `perfectEquity` 直接读 `s.hole[0]` 与 `s.hole[1]`；
   `src/rollout.cpp:88-94` 的 `equityFor` 按 `boardN` 缓存后供 `phiOf` 使用，
   调用点 `rollout.cpp:2452`（开局）、`:2535`（critic extra）、`:2725`（差分塑形）。
   全库没有第二处“对随机范围”的胜率：`handStrength` 是 vs 随机的**手牌百分位表**（进 actor），
   `rangeEquityFor`（`rollout.cpp:441-553`）是**按对手动作似然加权的范围胜率**（仅 actor，默认关）。
2. **精确/采样**：河牌 1 种（精确，0.5µs）、转牌 44 种（精确，5.1µs）、
   翻牌 C(45,2)=990 种（**默认 MC 32 次**，6.5µs）、翻前 C(48,5)=1,712,304 种
   （**MC 32 次**，8.4µs）。整手 4 条街合计 ≈ **20.5µs CPU**；每 update 512 局、
   0.93 upd/s、2 worker ≈ **4.5ms CPU/手 → 胜率占 rollout 约 0.45%**（单决策 <1%）。
3. **误差**（`/tmp/eqcheck.cpp`，对同一量做全枚举对拍）：

| 街 | 采样误差（MC32 vs 精确 2+2+N） | MC160 | 单次耗时 |
|---|---:|---:|---:|
| 翻前 | MAE 0.0698 / MAX 0.204 | — | 8.4µs（512 次 = 133µs） |
| 翻牌 | MAE 0.0495 / MAX 0.233 | MAE 0.0227 / MAX 0.099 | 6.5µs（精确 990 = 89µs） |
| 转牌 | 0（精确） | — | 5.1µs |
| 河牌 | 0（精确） | — | 0.5µs |

4. **与 `texas_algorithm` 的关系**：其 `GetHandProbability` 定义是“2 张手牌 + N 张公牌
   **对一个均匀随机对手**”（`cpp/texas_algorithm_util.h:238-243`）。我们用它做了两件事：
   - **对拍校验**：把“我们自己的 2+N 全枚举”与它的表逐点比较，翻牌 n=20、转牌 n=30、
     河牌 n=60 全部 **MAE = 0.0000**；翻前表 vs 我们 MC4096(2+N) MAE 0.0058
     → 我们的 `evaluate7` 与牌编码映射完全正确，**采样误差之外没有系统性偏差**。
   - **语义差**：`phi(2+2+N) − 表(2+N)` 在同一牌面上 **翻前 MAE 0.097 / 翻牌 0.193 /
     转牌 0.215 / 河牌 0.321（MAX 0.956）**。河牌最极端：知道对手底牌时胜率是 0/0.5/1，
     对随机范围则是一个排名分位。**用表替换等于换了一个条件量**，会把大池的势能信号
     整体改写，不能做“去噪”，只能做新实验。
5. **对手手牌不是均匀随机**：phi 用真实底牌（完全信息）。所以“大池打不好 = 把对手当均匀随机”
   不成立；actor 侧真正缺的是**范围**信息（默认 `--range-eq 0`）。`--range-eq N` 的路径是
   `rollout.cpp:441` 起：采样 M 个对手组合 → 用对手最近动作的策略似然做贝叶斯重加权 →
   算我方 vs 该范围的摊牌胜率（每次 48 次 MC，转/河精确），作为 actor 的输入特征；
   成本 ≈ M×(观测编码 + 1 次批量前向 + 1 次 48 迭代胜率)。历史外部结果：
   `rangeEq16` 24k 手只 **+0.16（0.8σ）**、`stn2` 反向 −0.53、`rangeEq32/96` −0.85（2988 手）、
   经验范围模型 −0.60（5698 手）→ 所以现役配置是 0。
6. **2+2+N 建表成本**：状态 = 手牌对 × 公牌组合，翻前约 1.6M 牌型对 × 1.7M 发牌
   ≈ **2.8e12 次评估**，不可行；可行的是**在线精确枚举**（转/河已精确，翻牌 990 种 = 89µs）。
   故 R9 只做“在线精确”，不建表。
